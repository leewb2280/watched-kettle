# ADR 0004: 12단계 성능 측정에 따른 Python 유지와 부분 개선

- 상태: 승인·구현 완료 — 2026-10-02 1차 측정으로 결정, 같은 날 개선 후 재측정에서 모든 목표 통과
- 근거: 12단계 측정 계획과 2차 측정 결과(개선 후, 2026-10-02). 아래 수치는 그 결과에서 옮겼다.

## 결정

1. **앱 본체는 Python·PySide6를 유지한다.** 시작(T2 0.51/0.65초), 유휴 메모리(T3 61.4/77.7 MiB), 60분 동안의 Python 본체 메모리(+0.4 MiB 이하)가
   목표 안에 있다. 크기(T7)는 대부분 Electron이 차지해 Python 교체로 줄일 여지가 없다.
2. **설정창 숨김 상주(T4·T6)는 Python 안에서 고친다.** 숨긴 지 5분이 지나면 Electron 자식 프로세스를 종료하고 다음 열기에서 새로 실행한다.
   (2026-11-04에 1분으로 줄였다. 아래 [추가 조정](#추가-조정-2026-11-04) 참고)
   새로 실행해도 첫 열기가 약 0.5초라 T5(1.5초)를 지킨다. 숨김 중 메모리는 유휴 수준으로 돌아갈 것으로 예상한다. 언어 교체가 아니다.
3. **hook 브리지(T1)는 Python 경량 실행 파일을 먼저 시도한다.** bridge를 PySide6 없는 별도 실행 파일로 분리하고 import를 줄인 뒤 같은 조건으로
   다시 측정한다. p95가 100ms 이하이면 Python을 유지한다. 넘으면 네이티브 bridge 교체로 넘어가 후보 언어를 비교한다.
4. **Electron 언어 팩은 한국어·영어만 포함한다.** hook 실행 파일(약 1.75MB)을 더하자 펫+비서 ZIP이 214.2MiB로 T7(212.6MiB)을 넘었다.
   앱 UI는 한국어 전용이고 Chromium은 다른 시스템 언어에서 en-US로 돌아가므로 나머지 53개(약 48MiB)를 뺀다. 재측정 뒤 사용자 승인으로 추가했다.

## 이유

- 판정 규칙: 목표 안이면 유지, 설계 문제는 Python 안에서 고치고, 언어를 바꿔야만 목표에 들어올 때만 교체한다.
- T4·T6의 원인은 숨김 중 Electron 상주라는 정책 문제다.
- T1은 PySide6 런타임 hook과 import가 약 100ms를 차지한다. 이를 뺀 시제품이 p95 100.8ms로 경계에 있어, 언어 교체가 필요한지는 아직 판단할 수 없다.

## 결과

- **설정창:** 숨김 5분 뒤 Electron을 종료한다. 숨김 5분 뒤 트리 합계 63.2/82.1MiB, 다시 열기 451/477ms, 60분 열기·숨기기 증가 0.8/0.0MiB.
- **hook:** 펫+비서 구성에 `CodexPetsHookBridge.exe`를 추가했다. PySide6·PIL만 뺀 상태는 p95 100.1ms로 여전히 경계였고,
  `inspect`·`dataclasses`까지 빼 PyInstaller의 inspect 런타임 hook을 없애자 p95 82.9ms(수신자 없음 82.5ms)가 됐다. **Python을 유지하고 네이티브 교체는 하지 않는다.**
- **크기:** 언어 팩 정리 뒤 번들 458.3/462.3MiB, ZIP 199.2/202.2MiB.

## 위험과 후속

- hook 여유는 빈 PyInstaller 실행 파일(약 75ms) 위에서 약 17ms다. 더 느린 PC에서는 목표를 넘을 수 있으므로 15단계 실환경에서 다시 본다.
  넘으면 네이티브 bridge를 다시 검토한다. 툴체인·CI·서명 대상·hook 이벤트 정규화의 두 언어 계약 검사가 늘어나는 비용은 그대로다.
- bridge에 `inspect`·`dataclasses`를 import하는 코드가 들어가면 빌드 경계 검사(`scripts/check_edition_modules.py --edition hook-bridge`)가 실패한다.
- 이전 버전에서 등록한 hook은 앱 실행 파일 경로를 가리켜 연동 화면에서 "경로 변경"으로 보인다. 예전 `--codex-hook-bridge` 경로는 계속 동작하며,
  복구하면 새 실행 파일로 바뀐다. 13단계 Claude Code hook도 같은 실행 파일을 쓴다.
- 숨김 5분 뒤 다시 열기는 Electron을 새로 시작해 약 0.5초가 걸린다. 14단계에서 비서 센터를 Electron으로 통합하면 열기 빈도가 늘어나므로 같은 측정으로 다시 확인한다.

## 재설정 (2026-10-30, 1.0 전 전체 검수)

12단계 목표는 그 뒤 더한 기능(13단계 Claude Code 연동, 말풍선 꾸미기, 사용량 기록) 전의 값이다. 1.0 전 검수에서 App Server 쪽 비용을 먼저 줄인 뒤
(계정 확인 60초 → 5분, 표준입력을 닫아 즉시 종료, 턴 상태 클라이언트 유휴 1분 뒤 종료) 같은 방법으로 다시 재고 T3를 새로 정했다.

| 지표 | 이전 목표 | 측정(main `36a047a` Public 번들, 이 PC) | 새 목표 |
|---|---|---|---|
| T3 펫만 유휴 트리 합계 | 80MiB | 77.0MiB | 90MiB |
| T3 펫+비서 유휴 트리 합계 | 150MiB | 173.2MiB(본체 약 116MiB, `codex.exe` 2개 약 55MiB) | 200MiB |
| T4 설정창 숨김 5분 뒤 | T3 + 30MiB | 170.9·174.9MiB | T3 + 30MiB(그대로) |

- T1은 훅 실행 파일에서 메시지 카탈로그·babel을 빼 p95 85.3ms가 됐다. 0.15.6부터 babel이 pkgutil·multiprocessing 런타임 hook을 끌어와 100ms를 넘고 있었다.
  빌드 경계 검사(`HOOK_BRIDGE_FORBIDDEN`)가 이 모듈들을 막는다.
- 남은 `codex.exe` 2개는 사용량 클라이언트와 대화 메타데이터 클라이언트다. 메타데이터 쪽은 App Server의 실시간 알림을 받으므로 유휴 종료하지 않았고,
  하나로 합치는 것은 알림 경로를 다시 짜야 해서 하지 않았다. 다시 줄이려면 이 통합이 다음 후보다.
- 측정 한계: 개발 PC 한 대의 자동 측정이다. 실환경 장시간·배터리 측정은 수동 QA 항목으로 남긴다.

## 추가 조정 (2026-11-04)

사용자 지인의 "램 최적화" 의견으로 남은 상주 비용을 다시 봤다. 수치는 이 PC의 소스 실행 자동 측정이며 실환경 검수가 아니다.

| 항목 | 변경 | 측정 |
|---|---|---|
| 설정창 연 동안 Electron | 앱 설정 "설정창 하드웨어 가속"(기본 켬). 끄면 GPU 합성을 쓰지 않는다 | 끄면 트리 합계 236.3 → 118.6MiB. GPU 프로세스 138.7 → 19.3MiB, main·renderer·NetworkService는 거의 같음 |
| 설정창 숨김 상주 | 종료 대기 5분 → 1분. 다시 연 창은 이번 실행에서 고른 탭을 유지 | 숨긴 뒤 75초 안에 Electron 종료 확인 |
| 대화 메타데이터 App Server | 조회 대상과 대기 중인 조회가 없는 상태가 60초 이어지면 닫고, 다음 조회 대상이 생기면 다시 연다 | 조회 대상이 없는 동안 `codex.exe` 1개(약 35MiB) 감소 |
| 사용량 위젯 | 위젯을 끄면 Qt Quick 창을 닫는다. 펫만 숨기면 숨기기만 한다 | 숨긴 창 하나 약 19MiB. 닫으면 약 15MiB 반환, 반복해도 증가 없음 |
| 펫 프레임 | 칸마다 RGBA를 zlib 레벨 1로 압축해 두고 그릴 때 푼다. 최근 12장만 풀린 채로 둔다 | 프레임 단계 15.1 → 8.5MiB(mori-bot), 14.8 → 9.0MiB(사설 펫). 펫 로드 91 → 143ms |
| Codex App Server | 사용량·대화 메타데이터·턴 상태가 프로세스 하나를 공유한다(`AppServerHub`). 계정 확인만 따로 띄운다 | Codex를 쓰는 동안 `codex.exe` 2개 → 1개 |

- 측정 조건은 다음과 같다.
  - Electron: 격리 프로필, 연 상태 10~48초 구간의 프로세스 종류별 전용 메모리 중앙값.
  - 위젯: 별도 프로세스에서 QQuickView 생성·삭제 전후의 전용 메모리.
- Electron에서 같이 시험한 두 가지는 넣지 않았다.
  - 네트워크 서비스 프로세스 내 실행(`NetworkServiceInProcess`): Electron 44에서 별도 프로세스가 그대로 남았다.
  - 맞춤법 검사 끄기: 차이가 없었다.
- GPU 가속을 꺼도 창 내용은 같게 그려졌다(PrintWindow 비교). 아크릴 배경은 Windows가 합성하므로 실제 창에서 눈으로 확인하는 수동 항목으로 남긴다.
- 처음에는 항상 끄도록 했다가, 사용자 결정으로 기본은 켜 두고 앱 설정에서 끌 수 있게 했다. 끄면 화면 전환과 대화상자 뒤 흐림을 CPU가 그린다. 값은 `settingsUI/hardwareAcceleration`에 저장하고 host가 Electron을 띄울 때 `WATCHED_KETTLE_SETTINGS_GPU`로 넘긴다. 띄울 때와 값이 다르면 숨기는 즉시 종료해 다음 열기부터 적용한다.
- 위 [재설정](#재설정-2026-10-30-10-전-전체-검수)에서 메타데이터 App Server를 유휴 종료하지 않은 이유는 실시간 알림이었다. 이 worker가 처리하는 알림은 `account/updated`뿐이고, 닫혀 있는 동안의 계정 변경은 다시 연결할 때 계정을 먼저 읽어 확인한다. 이름 조회는 첫 표시를 막지 않으므로(BA-09) 다시 연결하는 동안에는 이름 확정만 늦어진다.
- 소스 30분 합성 측정(`scripts.runtime_check --source --memory-diagnostics`)에서 본체는 112.6MiB였다. 준비 시간 뒤 증가는 +1.7MiB, 마지막 10분 증가는 0MiB로 누수 징후가 없었다.
  설치판 0.15.11을 23시간 쓴 상태에서 1시간 수동 관측(`scripts.observe_process`, 그동안 Claude Code 작업 계속)한 결과는 148.5 → 152.9MiB였다. 25~30분 대비 55~60분 구간 중앙값 증가는 +1.8MiB로 T6(5MiB 이하) 안이다. 10월 20분 측정(약 116MiB)보다 높은 차이는 실사용에서 채워지는 기록·캐시로 보며, 6시간 연속 사용 항목에서 다시 본다.
- 사용량 쪽 App Server는 5분 한도 갱신과 알림 때문에 유지한다. 이제 메타데이터·턴 상태도 같은 프로세스를 쓰므로 Codex를 쓰는 동안에도 상주 프로세스는 하나다. 기능마다 연결 창구를 따로 닫을 수 있고, 모든 창구가 닫히면 프로세스가 끝난다. 사용량 창구를 닫았다 열면(계정 전환) 프로세스를 재시작한다.
- 펫 프레임을 압축해 두므로 외형이 여러 개인 펫도 외형마다 약 6MiB만 늘어난다. 외형 변형의 지연 로드는 따로 하지 않는다. 압축은 PNG·무손실 WebP가 더 작지만 압축에 140~230ms가 걸려 zlib 레벨 1을 골랐다.
- 두 변경 뒤 공개 번들 20분 유휴(같은 PC, 15~20분 구간 중앙값): 트리 합계 179.5 → 145.9MiB, 본체 118.4 → 112.0MiB, `codex.exe` 2개 58.7MiB → 1개 32.8MiB. 측정 중 이 PC에서 Codex 데스크톱 앱이 실행 중이었다.
- T4 지표 이름의 "숨김 5분 뒤"는 이제 "숨김 1분 뒤"에 해당한다. T3 목표(90/200MiB)는 바꾸지 않는다.
