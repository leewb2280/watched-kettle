# ADR 0009: 자동 업데이트는 변경분만 받아 두고 다음 시작 때 적용한다

- 상태: 승인 — 2026-10-21, 0.15.10부터 적용
- 관련: [ADR 0007](0007-partial-updates.md), [ADR 0008](0008-update-repository.md), 릴리스 절차 4절 사용자 요청 업데이트

## 배경

0.15.4부터 설치판은 하루에 한 번 새 버전을 확인하고 펫이 알리기만 했다. 내려받기와 설치는 사용자가 `업데이트`를 누를 때만 했다.
알림을 놓치거나 미루면 오래된 버전이 남고, 직전 3개 버전을 넘으면 변경분 대신 큰 설치 파일을 받아야 한다.

설치기는 앱을 끝내야 실행된다. 반면 변경분은 앱이 켜진 채 `runtime\<구성>.next`를 만들 수 있다. 실행기는 일반 시작에서도 준비된 폴더를 한 번 바꿔 넣는다(ADR 0007). 그래서 실행기·설치기를 바꾸지 않고(설치기 개정 번호 유지) 앱 쪽만으로 자동 업데이트를 할 수 있다.

## 결정

- 설정 `업데이트 자동 설치`(`updates/autoInstall`, 기본 켜짐)를 둔다. `업데이트 자동 확인`이 켜져 있을 때만 의미가 있으며, 설정창은 자동 확인이 꺼져 있으면 스위치를 비활성화한다. 0.15.9 이하에서 자동 확인을 끈 사용자는 자동 설치도 동작하지 않는다.
- 자동 확인이 새 버전을 찾으면, 그 Release에 이 버전·이 구성·같은 설치기 개정 번호의 변경분이 있을 때만 백그라운드로 내려받아 검증하고 `.next`를 준비한다. 사용자가 직접 누른 확인은 지금처럼 알리기만 한다.
- 준비가 끝나면 앱을 다시 켜지 않는다. 버전 줄은 `staged` 상태로 "다음에 앱을 시작할 때 적용"을 보이고, 펫은 버전마다 한 번 알린다. 사용자가 `지금 재시작`을 누르면 기존 변경분 경로처럼 실행기가 바로 바꿔 넣는다.
- 적용은 실행기를 거친 다음 시작 때다(시작 프로그램, 시작 메뉴, 바탕 화면 바로 가기). 앱 안의 언어 변경 재시작은 실행기를 거치지 않으므로 적용하지 않는다.
- 일반 시작에서 파일이 사용 중이라 바꾸지 못했으면 앱은 이 구성의 `.next`를 지우지 않고 `staged`로 남긴다. 다음 시작이 다시 시도한다. `.ready`의 버전이 현재 버전보다 높지 않은 `.next`, 다른 구성의 `.next`, 실행기가 실패를 기록한 시작의 `.next`는 기존대로 지운다.
- 변경분이 없거나(오래된 버전, 다른 개정 번호, 다른 구성) 내려받기·검증·준비가 실패하면 설치 파일을 자동으로 받지 않는다. 기존처럼 새 버전을 알리고 `업데이트` 버튼으로 남긴다. 실패는 사용자에게 오류로 보이지 않고 로그(`auto_update_stopped`)에만 남는다.
- `staged`인 동안 자동·수동 확인을 하지 않는다. 같은 버전을 다시 받지 않기 위해서다.

## 결과

- 0.15.10 설치판부터 적용된다. 0.15.9 이하 설치판은 이 규칙을 모르므로 0.15.10까지는 지금처럼 직접 업데이트한다. 자동 업데이트의 첫 실제 경로는 0.15.10 → 다음 버전이다.
- 사용 중인 앱이 스스로 종료되거나 펫이 사라지는 일은 없다. 대신 앱을 오래 켜 두면 적용이 늦어진다.
- 보내는 정보와 연결하는 서버는 수동 업데이트의 변경분 경로와 같다([개인정보 문서](../privacy-and-storage.md)). 내려받기는 사용자가 누르지 않아도 일어나므로 개인정보 문서와 사용자 안내에 적는다.
- 실행기·설치기·installer revision은 바꾸지 않는다.
