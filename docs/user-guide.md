## 설치와 실행

[Releases](https://github.com/leewb2280/watched-kettle/releases/latest)에서 설치 파일과 `.exe.sha256`을 받습니다.
[README의 SHA-256 확인 방법](../README.md#빠르게-시작하기)으로 비교한 뒤 설치 파일을 실행하세요.
설치 파일은 아직 코드 서명이 없어 SmartScreen 경고가 나올 수 있습니다. 출처와 해시를 확인했다면 `추가 정보 → 실행`으로 진행할 수 있습니다.

설치 파일(`WatchedKettle-<버전>-public-unsigned-setup.exe`)을 실행하면 관리자 권한 없이 현재 사용자에게 설치됩니다.
처음에 설치 언어(한국어/English)를 고릅니다. 앱도 처음에는 설치 언어를 따릅니다. 앱 설정의 언어에서 한국어·English 또는 사용자 언어팩을 고른 뒤 언어 카드 버튼 줄 오른쪽의 `앱 다시 시작`을 누르면 적용되고 앱 설정이 다시 열립니다. [언어팩 안내](language-packs.md)를 참고하세요.

1. **설치 구성**: `펫만` 또는 `펫 + 비서`를 고릅니다. 다시 설치할 때는 현재 구성이 미리 선택되어 있고,
   펫 + 비서에서 펫만으로 바꾸면 이 앱이 추가한 hook을 제거한다는 안내가 함께 나옵니다.
2. **사용할 도구**(펫 + 비서일 때만): `Codex`와 `Claude Code`를 각각 고릅니다. 새로 설치할 때는 이 PC에 각 도구의
   설정 폴더(`~/.codex`, `~/.claude`)가 있으면 미리 체크되어 있습니다. 고른 도구에만 이 앱의 hook을 설치하고
   사용량을 보여 주며, 고르지 않은 도구의 파일은 읽지 않습니다. 다시 설치할 때는 앱에서 켜 둔 도구가 미리
   선택되어 있고 바꾼 항목만 적용합니다. 설치한 뒤에는 [사용할 도구 켜고 끄기](#사용할-도구-켜고-끄기)에서 언제든 바꿀 수 있습니다.
3. **바로 가기와 자동 시작**: 바탕 화면 바로 가기와 Windows 로그인 시 자동 시작을 고릅니다. 자동 시작 체크는
   현재 등록 상태를 보여 주며, 바꿨을 때만 적용합니다.

시작 메뉴에는 폴더 없이 `Watched Kettle` 바로 가기 하나가 생깁니다. 바로 가기와 자동 시작은 설치 폴더의
`WatchedKettle.exe`(구성에 맞는 실행 파일을 여는 작은 실행기)를 가리키므로, 구성을 바꿔도 작업 표시줄 고정이나
바로 가기가 끊기지 않습니다.

선택 화면 없이 설치(`/SILENT`, `/VERYSILENT`)하면 현재 구성·사용할 도구·자동 시작을 그대로 둡니다. 새로 설치할 때는
펫만을 설치하고, 펫 + 비서를 고르더라도 `/CLAUDECODE=on`을 주지 않으면 Claude Code는 꺼 둡니다. 명령줄에서 `/EDITION=pet-only|pet-assistant`, `/CODEX=on|off`, `/CLAUDECODE=on|off`로
고를 수 있고, `/LANG=ko|en`을 주면 언어 선택 창을 건너뜁니다.

### 업데이트

자동 시작은 설정창의 `앱 설정`에서도 켜고 끌 수 있습니다. 새 버전 확인도 같은 화면의 `버전과 업데이트`에서 합니다.
`업데이트 확인`을 눌러 새 버전이 있으면 받을 크기와 함께 알려 주고, `업데이트`를 누릅니다. 가능하면 바뀐 파일만 받아
새 프로그램을 옆에 준비해 두고(`업데이트를 준비하는 중…`), 펫이 "업데이트를 설치하고 곧 다시 켜집니다"라고 알린 뒤
앱이 종료되고 몇 초 안에 새 버전으로 다시 켜집니다. 바뀐 파일만 받을 수 없으면(오래된 버전, 준비 실패 등) 이 구성용 설치
파일을 받아 화면에 창 없이 설치하고 20~30초 뒤 다시 켜집니다. 구성·사용할 도구·설정·펫은 그대로 남습니다. 설치에 실패하면 오류 창이 뜹니다.

`업데이트 자동 확인`(기본 켜짐)을 켜 두면 설치판이 하루에 한 번 새 버전이 있는지 확인합니다. 새 버전을 찾으면 펫이
"새 버전이 나왔어요"라고 한 번 알리고, 트레이 메뉴의 `업데이트 확인`이 `새 버전 받기 (v<버전>)`로 바뀝니다. 말풍선이 꺼져
있거나 쉬는 중, 펫을 숨긴 동안에는 말풍선 없이 트레이와 설정창에만 표시합니다. 내려받기와 설치는 `업데이트`를 누를 때만
합니다. 확인에 실패해도 따로 알리지 않고 나중에 다시 확인합니다. 자동 확인을 끄면 `업데이트 확인`을 누를 때만 확인합니다.
트레이 메뉴의 `업데이트 확인`은 `앱 설정`의 버전 줄을 열고 바로 확인을 시작합니다.

업데이트한 뒤 처음 실행하면 펫이 "업데이트를 마쳤어요"라고 한 번 알립니다. 바뀐 점은 설정창의 `정보`에서 볼 수 있습니다.

### 앱 종료

설정창의 X는 설정창만 숨기고 펫은 계속 실행합니다. 펫까지 종료하려면
펫 우클릭 메뉴의 `종료`, 설정창 왼쪽 메뉴 아래의 `펫 앱 종료`, 또는 트레이 메뉴의 `종료`를 누릅니다.

### 제거와 데이터

제거는 Windows `설치된 앱`에서 합니다. 이 앱의 hook과 자동 시작을 정리하고, `데이터 유지`(기본)·`기록만 삭제`·
`모두 삭제` 중에서 고른 범위만 지웁니다. `기록만 삭제`는 비서 기록이 있을 때만 보이며, 사용자 펫과 설정은 남깁니다.
앱이 아무 데이터도 남기지 않았다면 데이터 선택 창 없이 제거 확인만 묻습니다.

설치·업그레이드·제거 중에 펫이 실행 중이면 먼저 펫과 설정창을 정상 종료합니다. 10초 안에 종료되지 않으면
강제로 종료할지 묻고, `아니요`를 고르면 아무것도 바꾸지 않고 멈춥니다. 선택 화면 없이 실행하면 묻지 않고 강제로
종료합니다. `모두 삭제`는 다른 프로그램이 앱 데이터를 쓰고 있으면 아무것도 지우지 않고 제거를 멈추므로, 그
프로그램을 닫고 다시 제거하면 됩니다. 어떤 이유로 제거가 멈춰도 앱은 설치된 채 남아 다시 제거할 수 있습니다.

## 펫 기본 조작

- 왼쪽 드래그: 펫 이동
- 왼쪽 더블클릭: 손 흔들기와 설정창 홈 열기(기본값). `꾸미기 → 펫 → 동작·화면`의 `더블클릭 동작`에서 Codex 열기, Claude Code 열기 (VS Code), 손 흔들기만으로 바꿀 수 있습니다.
- 오른쪽 클릭: 설정창, 표시, 이동과 종료 메뉴
- 트레이 왼쪽 클릭: 펫 표시 또는 숨기기
- 트레이 오른쪽 클릭(펫+비서): 현재 상태와 사용량, 진행 중 프로젝트·최근 알림,
  `알림 잠시 쉬기`·`펫 숨기기`·`펫 고정`·`위젯 고정`, `홈 열기`·`사용량 보기`·`설정`·`업데이트 확인`, `종료`
- 트레이 오른쪽 클릭(펫만): `펫 숨기기`·`펫 고정`, `설정`·`업데이트 확인`, `종료`
- 트레이 아이콘: 펫 얼굴에 작업 중(파랑)·확인 필요(황토)·실패(적갈) 점이 붙습니다.

### 펫·위젯 고정

펫이나 사용량 위젯이 다른 앱의 버튼·글자를 가릴 때 고정하면, 클릭이 펫·위젯을 지나 뒤에 있는 창으로 갑니다.
고정해도 펫은 그대로 보이고 움직이며 마우스를 쳐다봅니다. 대신 드래그·더블클릭·우클릭 메뉴는 동작하지 않습니다.

- 펫 고정: 펫 우클릭 메뉴 `펫 고정`, 트레이 메뉴 `펫 고정`, `꾸미기 → 펫 → 동작·화면`의 `펫 고정`
- 위젯 고정(펫+비서): 펫 우클릭 메뉴 `사용량 위젯 → 위젯 고정`, 트레이 메뉴 `위젯 고정`, 위젯 설정의 `위젯 고정`
- 풀기: 트레이 메뉴에서 체크를 끄거나, 설정창에서 끄거나, 지정한 단축키를 다시 누릅니다.
  위젯 고정은 펫 우클릭 메뉴에서도 풀 수 있습니다.
- 단축키: `펫 고정 단축키`·`위젯 고정 단축키`에서 `단축키 지정`을 누르고 원하는 조합을 누릅니다.
  Ctrl이나 Alt와 함께 문자·숫자·F1–F24 키를 써야 하며, 처음에는 지정돼 있지 않습니다. 어느 앱을 쓰고 있든
  누르면 고정이 켜지고 꺼집니다. 다른 앱이 이미 쓰는 조합이면 `다른 앱이 이미 쓰는 단축키입니다`가 표시되니
  다른 조합을 지정해 주세요. 펫 고정과 위젯 고정에는 같은 조합을 쓸 수 없습니다.
- 펫+비서 구성에서는 `고정할 때 버튼 말풍선도 통과`를 켜면 펫을 고정한 동안 버튼이 있는 말풍선도 클릭되지 않습니다.
  기본값은 꺼짐이라 말풍선 버튼은 계속 누를 수 있습니다.

고정 상태와 단축키는 펫을 바꾸거나 앱을 다시 실행해도 유지됩니다. 다만 트레이를 쓸 수 없는 환경에서
펫 고정 단축키도 없으면, 풀 방법이 없으므로 그 실행에서는 펫을 고정하지 않은 채 시작합니다.

## 펫 관리와 휴지통

`꾸미기 → 펫 → 펫 관리`에서 펫을 추가하고 이름으로 검색하거나 전체·표시 중·숨김으로 필터링합니다.
`목록에 표시`는 선택 목록·트레이 노출 여부이며 현재 사용하는 펫과 별개입니다. 현재 펫은 숨길 수 없습니다.
변경은 즉시 저장합니다. 순서 편집은 전체 목록에서 하며 드래그와 위·아래 이동 버튼을 사용할 수 있습니다.

- 사용자 펫의 더보기 메뉴에서 휴지통으로 옮깁니다. 사용 중이면 대체 펫을 먼저 고릅니다. 이동 직후 실행 취소를 제공하며 기본 제공·외부 경로의 펫은 삭제 대신 숨길 수 있습니다.
- 휴지통은 Windows 휴지통과 별도이고 자동 만료하지 않습니다. 복원하면 개별 설정·표시 여부·가능한 이전 순서를 되찾고 현재 펫은 유지합니다. 같은 ID·폴더가 이미 있으면 덮어쓰지 않습니다.
- 영구 삭제·휴지통 비우기는 확인 후 패키지와 해당 펫의 개별 설정을 지웁니다. 원래 가져온 외부 이미지와 다른 펫·앱 설정·기록은 지우지 않습니다. 같은 ID의 펫이 목록에 다시 있으면 휴지통의 파일만 지우고 목록 펫의 설정은 유지합니다.
- `선택`으로 현재 검색·필터·페이지에서 여러 항목을 이동·복원·영구 삭제할 수 있습니다. 페이지나 조건을 바꾸면 선택을 해제합니다. 휴지통은 한 페이지에 50개씩 표시합니다.
- 일괄 작업의 진행률·성공·실패를 확인하고 남은 작업을 중단할 수 있습니다. 완료한 항목은 유지합니다. 설정창을 숨겼다가 열어도 진행 상황을 다시 볼 수 있습니다. 앱 종료 시 아직 시작하지 않은 항목은 자동 재개하지 않습니다.
- 파일 잠금이나 복원 충돌은 실패 항목을 남깁니다. 원인을 해결한 뒤 다시 시도하세요. 손상되거나 읽을 수 없는 기록은 임의 삭제하지 않고 안내합니다. 같은 펫을 다시 가져오면 휴지통 복원을 제안합니다.

## 설정창과 첫 연결 확인

설정창 왼쪽 메뉴는 `홈`, `비서`(사용량·알림 기록·연결·진단), `꾸미기`(펫·말풍선·위젯), `정보`, `앱 설정`으로 나뉩니다.
펫만 구성에도 `홈`이 있으며 `꾸미기`의 펫·말풍선과 `정보`, `앱 설정`을 제공합니다. `비서`와 `꾸미기`는 선택 항목이 아니라 묶음 제목입니다.
설정값 선택 상자, 슬라이더와 화면 상단 탭은 마우스 휠로 바뀌지 않으며 클릭이나 키보드로 조작합니다.

`홈`은 두 구성에서 현재 펫·꾸미기 바로가기·더블클릭 동작을 표시합니다. 펫 + 비서 구성에는 확인할 알림, 진행 중인 대화, 남은 한도(Codex·Claude Code 영역을 나눠 표시), 사용 중인 도구의 연결 상태를
한 화면에 모아 보여 주고 각 화면으로 이어 줍니다. 트레이의 `홈 열기`가 홈을 엽니다.

### 정보 메뉴

`정보`는 버전과 설치 구성, 이번 버전의 새로운 기능, GitHub 저장소·버그 제보·라이선스 링크, 앱에 포함된 오픈소스 구성 요소의
라이선스를 보여 줍니다. 링크는 기본 브라우저로 열립니다. `변경 이력`은 지금까지의 모든 버전 Release 목록을 엽니다.
`라이선스 폴더 열기`는 설치판에서 각 라이선스 전문이 있는 폴더를 엽니다.
업데이트한 뒤 처음 실행하면 펫이 버전마다 한 번 "업데이트를 마쳤어요"라고 알리고 `정보`에서 새로운 기능을 볼 수 있다고 안내합니다.
말풍선이 꺼져 있거나 쉬는 중이면 보이지 않고 나중에 다시 보여 주지 않습니다.

### 첫 연결 확인

1. 펫을 우클릭하고 `설정`을 엽니다. 작업 상태를 보려면 `펫 + 비서` 구성이 필요합니다.
2. 연결할 Codex·Claude Code를 별도로 설치·로그인한 뒤, 설정창의 `연결·진단`을 엽니다.
3. 사용할 도구의 `Codex 사용`·`Claude Code 사용` 스위치를 확인합니다. 꺼져 있다면 켜고 변경 내용을 검토한 뒤
   `변경 적용`을 누릅니다. 설치할 때 이미 골랐다면 다시 적용할 필요가 없습니다.
4. 이미 열려 있던 Claude Code 세션을 다시 시작하고 새 작업을 실행합니다.
   `연결 점검`에서 최근 이벤트 수신을 확인하세요. Codex는 점검 결과에 신뢰 승인 안내가 있으면 따릅니다.
5. `Claude Code 사용`을 켜면 같은 곳의 `한도 가져오기`도 함께 켜집니다. 한도만 끄려면 이 스위치를 끕니다.
   한도는 지원되는 claude.ai Pro·Max 구독의 터미널 세션에서 첫 응답 이후에 들어옵니다.
   VS Code 확장 패널만 사용하면 갱신되지 않습니다.

펫만 구성에는 연결 메뉴가 없습니다. 연결이 실패해도 펫은 계속 동작합니다.

### 사용할 도구 켜고 끄기

`연결·진단`에서 **Codex 사용**과 **Claude Code 사용**을 각각 켜고 끕니다. 적용하기 전에 바뀌는 내용을 먼저 보여 줍니다.

- 켜면 그 도구의 사용자 설정에 이 앱의 hook만 추가하고 작업 상태와 사용량을 보여 줍니다. 도구 설정에서 hook이
  막혀 있어도 켜지며, 활동 표시가 제한된다는 안내가 나옵니다. Codex는 hook 없이도 작업 기록으로 상태를 일부 받습니다.
- 끄면 이 앱이 추가한 hook(Claude Code는 한도를 받던 status line 포함)을 지우고, 그 도구의 파일을 더 읽지 않으며,
  홈·사용량·기록·트레이·위젯에서 숨깁니다. 진행 중으로 보이던 카드도 지웁니다. 저장된 사용량 기록은 남아 있어
  다시 켜면 보입니다. 더블클릭에서 명시적으로 선택한 Codex 열기는 이 수집 스위치와 독립적입니다.
- 꺼진 도구는 연결·진단에 스위치와 짧은 설명만 남습니다.
- 켜 둔 도구의 hook이 지워지거나 바뀌면 펫이 말풍선으로 "연결이 풀렸어요"라고 알리고, 트레이 메뉴 첫 줄과
  설정 홈의 `연결`에도 표시합니다. 누르면 `연결·진단`이 열립니다. 고칠 때까지 앱을 실행할 때마다 한 번 알립니다.
- 앱을 설치한 뒤에 Codex나 Claude Code를 새로 설치하면 한 번 "찾았어요"라고 알립니다. 설치할 때 이미 있던 도구는
  다시 묻지 않습니다.

지원 환경과 확인 수준은 [지원 범위](support-scope.md), 상세 점검 항목은
[알림 기록과 연결·진단](#알림-기록과-연결진단)을 참고하세요.

## 상태 표시

- `idle`: 대기 중
- `running`: 작업 또는 도구 실행 중
- `review`: 생각하거나 결과 정리 중
- `waiting`: 사용자 확인이나 권한 대기
- `jumping`: 작업 완료
- `failed`: 작업 종료 실패

도구 하나의 실패는 전체 작업 실패로 표시하지 않습니다. 다른 작업이 진행 중이어도
완료된 주 작업의 알림은 유지합니다.

## 프로젝트 말풍선

프로젝트 말풍선은 진행·확인 필요·완료를 함께 표시합니다.
프로젝트 카드는 최대 3개이며, 나머지 프로젝트는 더보기로 확인합니다.
사용량·시스템 안내 1개와 일정 알림 1개는 별도로 유지합니다.

헤더는 `완료 N개 · 확인 필요 N개 · 작업 중 N개` 순서이며 0개인 항목을 숨깁니다.
프로젝트명과 상태 개수는 생략 없이 한 줄로 표시합니다. 헤더 전체가 필요한 경우 테마의 최대 너비를 넘어
말풍선을 넓히며, 화면 너비 자체를 넘을 때만 헤더 글자 크기를 줄입니다. 문구가 짧아지면 너비도 다시 줄어듭니다.
개수에는 스크롤 아래 대화도 포함됩니다. 대화는 완료 → 확인 필요·실패 → 중단 → 작업 중·검토 중
순서로 정렬하고, 같은 상태 그룹에서는 최신순으로 표시합니다. 도구 활동이나 제목 갱신만으로 순서를 바꾸지 않습니다.
처음 두 행이 온전히 보이며 나머지는 같은 말풍선 안에서 세로로 스크롤합니다.
한 행만 있으면 높이가 줄고 작은 화면에서는 한 행 높이까지 줄여 스크롤합니다.
헤더는 고정되며 아래를 보고 있을 때 새 완료가 들어와도 보던 대화를 유지합니다.

제목 오른쪽에는 상태 배지가 있습니다. 완료는 초록색, 확인 필요는 노란색,
실패는 붉은색, 중단은 회색이며 작업 중·검토 중은 배경 없는 문구입니다.
제목·헤더·버튼에 맞춰 너비가 자동 조절되며, 제목은 최대 두 줄에서 생략합니다.
마우스를 올리거나 접근성 기능을 이용하면 전체 제목을 확인할 수 있습니다.
제목은 정상 연결 상태에서 약 3초마다 조회합니다. 조회 실패 시 마지막 정상 제목을 유지하고,
아직 받은 제목이 없을 때만 `Codex 대화`를 표시합니다. 표시 중인 완료 대화도 갱신합니다.

새 대화는 프로젝트 관계를 먼저 확인해 기존 말풍선에 합류합니다. 최초 배치만 최대 1초
기다리며, 계속 미확인이면 `프로젝트 확인 중` 말풍선 한 개에 모읍니다. 이 문구는
프로젝트가 없는 것으로 확인된 `프로젝트 없는 대화`와 다릅니다. 펫의 작업 시작 반응은 기다리지 않습니다.

진행 중 새 활동 기록이 일반 작업 60초·도구 실행 180초 동안 없으면 행을 지우지 않고
회색 `상태 확인 중`으로 표시합니다. 헤더에서도 별도로 집계하며 새 활동을 받으면
원래 상태로 돌아옵니다. 제목 조회 성공만으로 작업 진행을 추정하지 않습니다.
확인 필요 대화는 사용자 응답을 기다리는 상태이므로 이 시간 제한을 적용하지 않습니다.
작업 도중 비동기 질문이 뜬 경우에도 `확인 필요`로 표시합니다. 질문을 띄운 직후 작업이
계속되더라도 같은 대화의 다음 사용자 메시지가 들어올 때까지 표시합니다. 질문이 여러 개면
사용자 메시지마다 가장 오래된 질문 한 건씩 해제합니다.

압축 시작 신호를 받으면 `컨텍스트 압축 중`으로 표시하고 헤더의 작업 중 개수에 포함합니다.
이 구간에는 일반 60초·180초 기준을 적용하지 않습니다. 시작 후 10분 동안 종료나 명확한
작업 재개가 감지되지 않으면 `상태 확인 중`으로 전환하지만 대화 행은 유지합니다.
종료 신호나 일반 도구 실행을 받으면 정상 상태로 돌아오며, 확인 요청·완료·실패·중단은 우선 표시합니다.
제목 갱신·연결 복구·일반 하트비트만으로 압축 종료를 추정하지 않습니다.
압축 시작 후크가 전달되지 않는 환경에서는 압축을 추정하지 않으므로 기존 활동 공백 표시가 적용될 수 있습니다.

작업 시작 없이 도착한 도구 반환은 새 작업으로 표시하지 않습니다. 완료 뒤 늦게 도착한 반환도
완료 표시를 작업 중으로 되돌리지 않습니다. 펫을 작업 도중 켠 경우에는 수집 시작 이후의
대화 식별자·호출 식별자가 있는 도구 시작으로 진행을 감지할 수 있습니다. 이미 종료를 확인한
대화는 새 작업 시작 또는 다른 작업 회차가 확인돼야 다시 작업 중으로 표시합니다.

종료가 확인되지 않은 행은 시간만으로 삭제하지 않고 명시적인 종료·앱 재시작·확인된 계정 초기화까지 유지합니다.

말풍선은 펫 위에 한 열로 쌓입니다. 화면 경계에서는 해당 방향의 이동만 멈추고
펫이 안쪽으로 돌아오면 다시 따라갑니다. 펫 이동과 주기 갱신에서는 기존 창과 행을 재사용합니다.
상단 모서리에서 펫이 제목을 가리게 되면 말풍선 열을 옆의 빈 공간으로 옮깁니다.
양옆이 좁으면 아래 공간을 사용하며, 공간이 생기면 원래 위쪽 위치로 돌아옵니다.

### 완료 표시와 기록

정상 완료된 주 작업은 같은 대화 행에 초록색 `완료` 배지와 X가 나타납니다.
행 배경과 헤더의 완료 개수를 기본 15초간 강조하고, 이후에는 초록색 배지만 유지합니다.
완료 시점부터 최대 5분 뒤 행을 정리하며, X를 누르면 해당 완료 표시만 닫습니다.
같은 대화에서 다음 작업이 시작되면 X를 누르지 않아도 즉시 `작업 중`으로 돌아갑니다.
대화 행을 중복으로 만들지 않으며 남은 대화가 없으면 프로젝트 말풍선을 닫습니다.

Codex 대화 제목을 누르면 Codex 앱에서 그 대화를 엽니다. Claude Code 대화는 실행한 곳에 따라 다릅니다.
VS Code 확장 패널의 대화는 패널에서 그 대화 열기를 시도하며(`대화 열기`, 실제 클릭 동작은 미확인), VS Code 내장 터미널의 대화는 그 폴더의
VS Code 창을 앞으로 가져옵니다(`창 열기`). 다른 터미널에서 실행 중인 대화는 앱이 그 창을 찾을 수 없어
설정창 활동 목록을 엽니다(`목록 보기`). 실행 중인 터미널 대화를 다른 곳에서 다시 열지는 않습니다.

Claude Code가 백그라운드 명령이나 하위 에이전트를 남기고 응답을 마치면 행이 `백그라운드 N개`로 바뀝니다.
이때 펫은 쉬는 모습으로 돌아가고, 백그라운드 작업이 끝나 Claude Code가 결과를 읽고 마무리하면 `완료`가 한 번 표시됩니다.

Codex와 Claude Code를 함께 쓰면 카드와 알림 머리글 앞에 출처 색 점(Codex 남색, Claude Code 주황)이
붙습니다. 한 도구만 쓰면 점을 붙이지 않습니다. 머리글에 마우스를 올리면 출처 이름이 보입니다.

제목 클릭은 대화 열기만 수행합니다. 링크 요청 성공·실패 또는 Codex 홈으로 이동한 경우에도
완료 표시는 유지하고 읽음 여부를 추정하지 않습니다. 실패·중단·하위 에이전트 종료·연결 끊김은
정상 완료 기록으로 만들지 않습니다. 실패·중단은 기존 표시 시간을 유지합니다.

지난 완료는 설정창 `알림 기록`의 `최근 활동`에서 완료 시각·대화 제목·완료 상태와 대화 열기로 확인합니다.
X·5분 만료·다음 작업 시작은 말풍선 표시만 정리하고 이력은 삭제하지 않습니다.
완료 이력은 최근 100건을 메모리에만 보관하며, 표시 중인 완료는 이 상한과 별도로 관리합니다.
앱 재시작 또는 확인된 계정 변경·로그아웃 시 이력을 비웁니다. 제목 조회 연결의 일시 단절은 진행 행과 이력을 지우지 않습니다. 제목·식별자를 새로 디스크에 저장하지 않습니다.
별도 완료 카드·최근 완료 배지·전용 목록 창은 제공하지 않습니다.

`표시 시간`의 `완료 강조`는 기본 15초, 범위 5~60초이며 기존 설정 키를 유지합니다.
공통 시간과 독립적이고 변경한 값은 이후 완료부터 적용됩니다. 완료 행의 5분 제한은 고정입니다.
알림 끄기·알림 잠시 쉬기·펫 숨김 중에도 시간은 흐르며, 복귀할 때 만료된 완료를 다시 표시하지 않습니다.

### 다른 알림의 표시 시간

실패·중단 결과·사용량·시스템·일정은 공통 표시 시간을 사용하며 기본값은 8초입니다.
`꾸미기 → 말풍선`의 `표시 시간`에서 `공통 표시 시간`을 5~60초로 조절할 수 있습니다.
같은 영역의 종류별 `개별 시간 사용` 스위치를 켜면 현재 적용 중인 시간을 시작값으로 삼아
해당 종류만 5~60초로 지정합니다. 스위치를 끄면 별도 값을 해제해 실패·일반·일정은 현재
공통 시간을 다시 사용하고, 완료 강조는 독립 기본값 15초를 사용합니다.
`종류별 시간을 기본값으로`는 공통 시간을 유지한 채 네 종류의 별도 값만 모두 해제합니다.
기존 표시 시간 설정은 공통 값으로 이어받으며 일정도 별도 설정이 없으면 공통 값을 사용합니다.
진행 중·검토 중·확인 대기는 상태가 유지되는 동안 표시합니다. 종료 결과의 시간은 종료 시,
그 외 알림의 시간은 실제 표시 시작 시 확정하며 이미 표시 중인 타이머는 설정 변경으로 바뀌지 않습니다.
자동 만료는 확인으로 처리하지 않습니다.
알림 상세를 열면 확인 처리됩니다. 알림 잠시 쉬기 동안의 알림은 이력에서 확인하며 쉬기가 끝난 후
몰아서 재생하지 않습니다. 프로젝트 이벤트(상태 변화 20건·확인 필요 50건), 일반 알림 50건의 세션 이력은 재시작 후 복원되지 않습니다.

`펫에서 미리보기`는 말풍선 페이지 상단의 꾸미기 카드에서 실행합니다. 비서 구성의
`알림 잠시 쉬기` 카드는 평상시 15·30·60분 선택만, 쉬는 중에는 남은 시간과
`지금 다시 표시`만 보여 줍니다. 쉬는 동안에는 프로젝트 진행·완료 카드를 포함한 말풍선을 모두
숨기며, 그동안 온 일반·일정 알림은 나중에 다시 띄우지 않습니다. 아직 진행 중인 작업은 다시
표시할 때 나타납니다. 말풍선 알림을 끈 상태에서는 새 쉬기 시간을 선택할 수 없습니다.
펫만 구성은 말풍선 꾸미기와 펫에서 미리보기만 제공합니다.

2026-09-05 검수본은 Codex Windows x64 26.901.5003.0에서 제목 클릭으로 정확한 대화 이동을 확인했습니다.
최신 완료 통합 소스에서 원하는 대화에 도착하는 동작은 사용자가 수동으로 확인했습니다.
미검증 버전이나 이동 실패 시에는 `Codex 열기` 또는 연결 안내로 대체합니다.
Codex만 열린 경우에는 해당 대화로 이동한 것으로 처리하지 않습니다.
일정은 수신·표시 준비와 미리보기만 제공하며 사용자의 일정관리 시스템과 아직 연결하지 않았습니다.

## 사용량

설정창의 `사용량`에서 서버가 제공하는 일별 토큰 활동과 한도별 잔여율,
초기화 시각, 사용량 초기화 가능 횟수를 확인할 수 있습니다. `오늘 시간대별`에서 토큰을 고르면 이 Windows 사용자의 Codex JSONL 관측 차이를 표시하며 여러 계정의 활동을 포함할 수 있습니다. 한도를 고르면 현재 확인된 계정의 App Server 사용률 관측 차이만 표시합니다. 둘 다 공식 시간대별 통계가 아니며 관측이 없는 시간은 값 없음으로 둡니다. 로컬 한도 샘플을 계정 한도에 합산하지 않습니다.

### 사용량 위젯

사용량 화면은 사용 중인 도구만 보여 줍니다. 도구를 켜고 끄는 곳은 `연결·진단`입니다.
현황과 홈의 남은 한도는 두 도구를 별도 영역으로 보여 주고, reserve는 Codex 그룹의 마지막 카드로 표시합니다.

펫 옆의 사용량 위젯은 Codex와 Claude Code의 남은 한도를 함께 보여 줍니다.
꺼진 도구나 한 번도 값을 받지 못한 도구는 자리를 차지하지 않습니다. 두 도구를 모두 끄면
위젯이 숨겨집니다. 외관 설정은 `꾸미기 → 위젯`에 있습니다.
이 화면 위쪽의 미리보기는 펫 옆 위젯과 같은 방식으로 그린 모습이며 설정을 바꾸면 바로 반영됩니다.
`예시 값`을 누르거나 아직 받은 한도가 없으면 예시 값으로 보여 주고, `간단형`은 마우스를 올렸을 때 모양도 볼 수 있습니다.

- **위젯 모양**: `링 / Rings`(기본), `막대 / Bars`, `간단형 / Compact` 중에서 고릅니다. 간단형은 마우스를 올리면 초기화 시각과 다른 한도를 펼쳐 보여 줍니다.
- **크게 보여 줄 한도**: 5시간·7일 한도 중 남은 양이 적은 쪽(자동), 5시간, 7일 중에서 고르며 두 도구에 함께 적용합니다. 다른 한도는 작은 글자로 표시합니다. 잔여 30% 미만은 주의 색, 10% 미만은 부족 색입니다.
- **작업 상태 표시**: 도구별 작업 중·확인 필요 개수를 표시합니다. 확인 필요가 있으면 그 개수를 먼저 보여 줍니다. 간단형에서는 두 도구에 같은 위치의 상태 점을 표시하며, 표시할 작업이 없으면 회색 계열, 작업 중이면 작업 색, 확인 필요이면 확인 색입니다. 마우스를 올리면 개수나 `표시할 작업 없음 / No tasks to show`를 보여 주며, 한도 정보가 없어도 작업 상태를 확인할 수 있습니다. 회색 점은 연결 정상이나 실제 대기 상태를 보장하지 않습니다. 이 설정을 끄면 상태 점과 작업 상태 문구를 모두 숨깁니다.
- **오늘 흐름 표시**(기본 꺼짐): 오늘 시간대별 토큰을 작은 막대로 그립니다. Codex는 이 기기 로그에서 관측한 값이라 관측하지 못한 시간은 옅은 짧은 막대로 구분하고, Claude Code는 대화 기록에서 끝난 턴의 토큰을 더합니다. `오늘 흐름 시간대`에서 표시할 시간대를 줄일 수 있습니다.
- **색**: 기본은 앱 테마(라이트·다크)를 따르고, `배경색 직접 지정`을 고르면 배경색을 정할 수 있습니다(배경 재질이 `단색`일 때). 색 창의 사각형에서 위아래로 움직이면 밝기, 좌우로 움직이면 진하기가 바뀝니다. 글자색은 배경 밝기에 맞춰 바뀝니다. `배경 농도`가 100%보다 낮으면 바탕화면 색이 섞여도 읽히도록 보조 글자를 본문 글자색으로 진하게 하고, 60% 아래에서는 글자에 외곽선을 더합니다. 어두운 바탕화면에서 밝은 카드를 반투명하게 쓰면 카드가 회색으로 보이므로, 그럴 때는 앱 테마를 다크로 두거나 배경 농도를 올리는 편이 보기 좋습니다.
- **배경 재질**: `단색`(기본)과 `아크릴` 중에서 고릅니다. 단색은 카드 색 한 가지로 그리며 `배경 농도`로 투명도를 조절합니다. 아크릴은 Windows 11에서 위젯 뒤를 흐리게 비추는 유리 효과로, 어두운 바탕화면에서도 카드가 탁해지지 않습니다. 앱 테마(라이트·다크)를 따르므로 아크릴일 때는 색 직접 지정과 배경 농도를 쓰지 않습니다. Windows의 투명 효과를 끄거나 고대비를 쓰면 1분 안에 단색으로 바뀝니다. 설정창 미리보기는 실제 유리 효과 대신 어두운 바탕 위의 색으로 보여 줍니다.
- **크기**: 70~130% 사이를 10% 단위로 조절합니다.

값이 15분 넘게 갱신되지 않으면 숫자와 링·막대를 회색으로 바꾸고 몇 분 전 값인지 알려 줍니다. 배경 농도를 낮춰도 글자는 투명해지지 않습니다. 연결 실패·로그인 필요·불러오는 중은 숫자 대신 짧은 문구로 표시합니다. Claude Code 한도는 터미널에서 Claude Code를 쓸 때만 갱신되며, 그 전에는 `한도는 터미널에서`라고 표시합니다. 초기화 시각이 지났는데 새 값이 없으면 `5시간 100%(추정)`처럼 `(추정)`을 붙인 추정값을 보여 줍니다. 큰 숫자에는 한도 이름 쪽에 붙습니다.

위젯을 클릭하면 설정창의 `사용량`을 엽니다. 처음에는 펫 옆에 붙어 이동하지만 배경을 끌면 그 자리에 고정되고 재실행 후에도 복원됩니다. 펫 우클릭의 `사용량 위젯` 메뉴에서 위젯 표시, 모양, 작업 상태·오늘 흐름 표시를 바꾸거나 `펫 옆으로 되돌리기`를 고를 수 있습니다. 이전 버전의 위젯 설정은 처음 실행할 때 한 번 새 설정으로 옮깁니다.

위젯과 작은 그래프 툴팁의 토큰은 `950`, `1.2K`, `4.1M`, `1.2B`, `1.2T`처럼
천 단위로 축약합니다. 소수점은 최대 한 자리이며 `.0`은 생략합니다. 반올림으로
`1000K`가 되면 `1M`으로 표시합니다. 설정창의 수치 카드·작업 표·상세 그래프 툴팁에서는
쉼표를 넣은 정확한 전체 토큰 수를 확인할 수 있습니다. 잔여율이나 토큰을 관측하지
못한 경우는 실제 0과 구분해 관찰 대기·기준 수집 중으로 안내합니다.

기기 토큰은 여러 계정의 로컬 활동을 포함할 수 있으며 계정 한도와 합산하지 않습니다. 계정 기록과 기기 관측 기록은 각각의 삭제 버튼으로 지웁니다. 기기 기록은 테이블별 8일/20,000건이며 이전 기록은 집계에서 제외한 채 별도로 열람할 수 있습니다.

Codex의 `현황`에서 `한도 상세와 계정 통계`를 펼치면 구간별 한도의 잔여율·초기화 시각·초기화 가능 횟수와 플랜·크레딧, 계정 누적 토큰·최대 일일 토큰·연속 활동일 같은 계정 통계를 확인합니다. 서버가 제공한 각 구간의 기간이 있으면 `5시간 한도`처럼 표시하며 요금제 이름만으로 없는 한도를 만들지 않습니다. 시간대별·일별 토큰과 남은 한도의 변화는 아래 `추이` 그래프에서 따로 보며, 단위가 다른 토큰과 한도 비율을 합산하거나 환산하지 않습니다.

연결이 정상일 때 공유 사용량 상태와 마지막 갱신 시각은 계정 이름 오른쪽에 한 줄로 표시합니다. 좁은 창에서 생략된 계정명·상태 문구는 마우스를 올리면 전체 내용을 확인할 수 있습니다. 연결 오류, 오래된 캐시, 부분 갱신 또는 기록 관련 안내가 있으면 별도 안내 배너로 표시합니다.

설정창의 `사용량`은 **현황 / 기록 / 설정** 탭으로 나뉩니다. 도구마다 수집은 `연결·진단`의 `Codex 사용`·`Claude Code 사용`으로 켜고 끄며, 둘 다 끄면 한도를 확인하지 않고 `새로고침`도 쓸 수 없습니다.

- **현황**: Codex와 Claude Code 영역으로 나눈 남은 한도 카드(잔여 30% 이상 `여유`, 10% 이상 `주의`, 그 아래 `부족`), 오늘의 기기 활동, `추이` 그래프를 보여 줍니다. Claude Code 한도 카드에는 마지막 관측 시각을 표시하고, 15분 넘게 지났으면 `오래된 값`을 붙입니다. Claude Code 한도는 터미널에서 Claude Code를 쓸 때만 갱신되므로 한동안 쓰지 않았거나 웹·데스크톱 앱에서 쓴 양은 반영되지 않습니다. 초기화 시각이 지났는데 새 값이 없으면 `추정` 표시와 함께 100% 남음으로 보여 주고, 5시간 한도는 `다음에 사용할 때 새로 시작`이라고 안내합니다(5시간 창은 다음 사용 때 시작되기 때문). 상단 줄은 켜진 도구마다 Codex 계정·플랜과 Claude Code 마지막 관측 시각을 보여 줍니다.

`추이`는 제목 오른쪽에서 `Codex | Claude Code`를, 카드 안에서 그래프 종류를 고릅니다. 사용하지 않는 도구는 홈·사용량 화면의 한도와 `추이`·`기록`의 도구 선택에서 빠지고, 한 도구만 켜져 있으면 선택 없이 그 도구만 보여 줍니다(설치할 때 고르지 않은 도구는 꺼진 채로 시작합니다). 다시 보려면 `연결·진단`에서 그 도구를 켭니다. 그래프 위에 요약 숫자를 두고, 막대나 선에 마우스를 올리면 정확한 값을 보여 줍니다. 관측값이 없거나 도구가 꺼져 있으면 빈 그래프 대신 안내를 표시합니다.

| 그래프 | 막대 | 선 | 요약 |
|---|---|---|---|
| 오늘 토큰 | 시간대별 토큰(지금 시간은 진하게) | 막대 뒤의 옅은 회색 면 = 지난 7일 중 기록이 있는 날의 같은 시간 평균(평소 모양). 관측하지 못한 시간은 비워 두고, 기록이 3일 미만이면 그리지 않음 | 오늘 합계, 평소 대비(지금 시간까지 비교), 가장 많이 쓴 시간 |
| 오늘 한도 | 없음 | 남은 한도 비율(0~100%). 세로 점선은 초기화, 옅은 점선은 마지막 관측 뒤 지금까지. `5시간 / 7일`을 그래프에서 고르며 위젯의 `크게 보여 줄 한도`와는 따로 고릅니다 | 지금 남은 한도, 오늘 줄어든 한도(%p, 초기화 뒤 첫 값은 기준으로만 사용), 초기화 횟수 |
| 일별 토큰 | 날짜별 토큰(오늘은 진하게) | 7일 이동 평균(가는 선, 7일 중 4일 이상 기록이 있을 때) | 기간 합계, 하루 평균, 가장 많이 쓴 날. 표시 기간은 7·14·30일 |

데이터 범위는 도구마다 다릅니다.

- **Codex**: 오늘 토큰은 이 PC의 Codex 로그 기준이며, 관측하지 못한 시간은 바닥에 옅게 표시합니다. 일별 토큰은 서버가 제공한 계정 전체(다른 PC 포함) 값입니다. 한도는 예비 한도를 뺀 기본 한도입니다.
- **Claude Code**: 오늘·일별 토큰 모두 이 PC의 대화 기록 기준이며, 끝난 턴의 토큰을 끝난 시간에 셉니다. 한도는 터미널에서 Claude Code를 쓸 때만 관측해 빈 시간이 있을 수 있습니다.
- **기록**: `Codex | Claude Code`를 골라 봅니다. 왼쪽에 프로젝트, 오른쪽에 선택한 프로젝트의 대화를 표시합니다. 프로젝트는 최신순·이름순(Codex는 사용자 지정도 가능), 대화는 최근 완료순·토큰순으로 정렬하며, 정렬은 고르는 즉시 반영되고 검색은 `Enter`나 `검색`으로 적용합니다. 대화를 누르면 작업 목록 창이 열리고, 작업 행을 눌러 토큰·예상 크레딧·모델 등 상세를 펼칩니다. 목록은 `이전 100건`·`다음 100건`으로 이동합니다. Claude Code 작업은 대화 기록 파일에서 턴별 토큰을 모으며 앱이 꺼져 있던 동안의 작업도 90일 안에서 가져옵니다. 도구 선택 오른쪽에는 그 도구의 기록 출처와 `기록 지우기`가 있습니다. Codex를 고르면 현재 계정의 작업 기록을, Claude Code를 고르면 이 기기에 저장한 Claude Code 작업 기록을 지웁니다(Claude Code의 대화 기록 파일은 건드리지 않습니다).
- **설정**: 사용량 알림과 `데이터 관리`(기기 관측 기록 삭제)가 있습니다. 삭제는 확인 창을 거쳐 실행합니다. 위젯 설정은 `꾸미기 → 위젯`으로 옮겼습니다.

Codex 작업별 토큰은 이 기기의 Codex 로그에서 같은 작업의 시작·완료와 누적값 차이를 확인해 계산합니다. 로그가 여러 파일로 나뉘면 이전 파일의 연결 경계까지 검증합니다. **부분 측정**은 작업 전체의 총 토큰은 확인됐지만 입력·출력·모델 등 일부 항목이 없는 경우입니다. 확인된 0토큰은 `0`, 알 수 없는 값은 `—`로 표시하며 측정 불가 기록은 사용량 순위에 넣지 않습니다. 계정 전체 사용량을 작업별로 나누어 넣지 않습니다.

기존 측정 불가 기록은 앱 시작·새 작업 완료·새로고침 때 다시 검사하고, 완료 후에는 연결 로그 없음·시작/완료 구간 미확인·토큰 기준값 미확인·누적값 감소 등의 사유를 상세에서 확인할 수 있습니다. 작업별 크레딧·USD는 로그에서 확인할 수 없어 측정 불가로 표시합니다. 계정 전환·로그아웃·기록 삭제 때는 이전 복구 결과가 뒤늦게 적용되지 않도록 취소합니다.

배경 농도를 0%로 설정해 카드가 보이지 않아도 위젯의 빈 배경 영역을 잡아 이동할 수
있습니다.

## 꾸미기

### 펫과 표시 설정

`꾸미기 → 펫`에서 펫, 크기, 시선 범위, 자동 행동, 자동 이동, 항상 위와 아래 항목을 설정합니다.
마지막 펫과 화면 위치는 다음 실행에 복원됩니다. 저장한 모니터가 사라지면 주 화면의 안전한 위치로 이동합니다.

- **펫 불투명도**: 50~100%(5% 단위, 기본 100%). 50% 아래는 바탕화면에서 펫을 찾기 어려워 막았습니다.
- **발밑 그림자**(기본 꺼짐): 펫 발밑에 옅은 그림자를 그립니다.
- **나타나고 사라질 때 부드럽게**(기본 켜짐): 펫을 숨기고 다시 보일 때 서서히 바뀝니다. `앱 설정`의 움직임 줄이기를 켜면 바로 나타나고 사라집니다.
- **펫 아래 현재 활동 표시**: 펫 아래 문구에 작업 중인 도구(Codex·Claude Code)를 색 점과 함께 보여 줍니다. 앱 테마 색을 따릅니다.

펫의 원본 스프라이트 셀은 `192×208px`입니다. 표시 너비 `112px`는 기본,
`192px`는 원본 크기, `224px`는 표준 최대, `352px`는 확장 최대입니다.
`80~224px`는 표준 크기이며 `256~352px`는 큰 화면용 확장 크기입니다.
설정 카드의 미리보기는 선택 크기를 1:1로 재현하지 않고 투명 여백을 제외한 기본 모습을
선명하게 맞춰 보여 줍니다. 실제 표시 크기는 카드 하단과 크기 조절 영역에서 확인합니다.

### 펫 가져오기

`꾸미기 → 펫 → 펫 가져오기`는 세 가지 입력을 받습니다. 펫만 구성에서도 제공합니다.

- **파일·폴더:** 웹 펫 설정에서 다운로드한 PNG/WebP, 펫 ZIP, `pet.json`이 있는 펫 폴더를 고릅니다.
- **설치 명령어:** CodexPetDB 또는 Pets Codex에서 복사한 설치 명령(예: `npx codexpetdb install <이름>`)을 붙여 넣고
  **다운로드**를 누릅니다. 명령을 실행하지 않고 펫 ID만 읽어 해당 서비스에서 직접 받으므로 Node.js나 별도 CLI가
  필요하지 않습니다. 이때만 인터넷에 연결합니다([개인정보와 저장](privacy-and-storage.md#네트워크와-설치기)).
  받는 중에 **취소**하고 바로 다시 받을 수 있습니다.
- **Codex에 설치된 펫:** Codex 사용자 폴더(`CODEX_HOME` 또는 `~/.codex`)의 `pets`에 있는 펫을 골라 복사합니다. 원본은 바꾸지 않습니다.

가져오기 창에서 이름과 9개 동작 미리보기를 확인하고 **추가**를 누르면 목록에 등록되며,
**이 펫 사용**으로 전환합니다. 추가만 하면 현재 펫은 유지됩니다. 패키지의 설명·제작자·크기·말풍선 장식 같은 지원 정보는
함께 가져오고, 가져오지 않는 정보는 등록 전에 알려 줍니다. 지원 범위와 상한은 [펫 패키지 규격](pet-package-format.md)을 따릅니다.

정지 PNG/WebP, 최대 20MiB, V1(1536×1872)·V2(1536×2288) 규격을 받으며 투명 배경과
필수 프레임을 검사합니다. 파일 선택은 10분 뒤 만료되므로 만료 안내가 나오면 다시 선택하세요.
같은 이미지는 기존 펫으로 재사용하며 이름·설정을 유지합니다. 이름이 같은 다른 이미지는
별도 펫으로 등록됩니다. 숨긴 기존 펫도 **이 펫 사용**을 누르면 목록에 다시 표시됩니다.
웹의 이름·설명·말풍선 장식은 이미지 파일만으로 자동 복원하지 않습니다. ZIP·폴더·설치 명령어로 가져오면 함께 들어옵니다.

등록한 펫은 `%LOCALAPPDATA%\WatchedKettle\pets`에 독립적으로 저장되어 원본 다운로드 파일을
지워도 사용할 수 있으며, 재시작 후에도 목록에 남습니다. 웹 계정 연결·자동 동기화·업로드는 하지 않습니다.
기존처럼 완성된 펫 폴더를 이 위치에 복사하고 목록을 새로고침해 추가할 수도 있습니다.
필수 파일이 없거나 복사 중인 폴더는 제외됩니다.

이전 이름(Codex Desktop Pets)으로 쓰던 `%LOCALAPPDATA%\CodexDesktopPets`의 설정·커스텀 펫·기록은
첫 실행 때 새 폴더로 자동으로 옮겨집니다.

### 말풍선 꾸미기

`꾸미기 → 말풍선`의 `말풍선 꾸미기`에서 디자인을 바꿉니다. 위쪽 프리셋(기본 크림·세이지·그라파이트·하늘·종이 노트·팝과
펫이 제공하는 테마)에서 시작하고, 항목은 색 / 모양·테두리 / 장식 / 사진·이미지 / 글자·여백 묶음을 펼쳐 조절합니다.
프리셋을 골라도 넣어 둔 사진·테두리 이미지·스티커는 그대로 둡니다.

- **배경 사진**: 말풍선 모양대로 잘라 그리며 진하기·초점·확대를 조절합니다. 사진은 말풍선 색 위에 진하기만큼 그려 글자가 읽히게 합니다.
- **테두리 이미지**: 그려진 테두리 대신 이미지를 9조각으로 늘여 씁니다. 모서리 크기를 정할 수 있습니다.
- **스티커**: 최대 3개를 위치·크기와 함께 붙입니다. 오른쪽 미리보기를 누르면 고른 스티커가 그 자리로 옮겨집니다.
- 이미지는 PNG·WebP·JPEG(20MB 이하)를 받습니다. 가져올 때 방향을 바로잡고 1024px 안으로 줄여 다시 저장하며, 사진의 위치 정보 등 메타데이터는 남기지 않습니다.
- 미리보기는 `짧은 알림`과 `프로젝트 카드`를 바꿔 볼 수 있고, 실제 말풍선과 같은 방식으로 그립니다.

## 알림 기록과 연결·진단

설정창의 `알림 기록`은 말풍선으로 지나간 알림과 이번 실행의 작업 이벤트를 다시 보는 곳입니다.
위에서부터 `확인하지 않은 알림`과 날짜별로 묶은 `최근 활동`을 보여 줍니다.

- `확인하지 않은 알림`은 5건까지 보이고 나머지는 `더 보기`로 펼칩니다. 알림을 누르면 상세로 이동하며
  확인 처리되고, `모두 확인`은 남은 알림을 한 번에 확인 처리하며 기다리던 알림 말풍선도 내립니다.
- `최근 활동`은 `알림`(비서 알림), `확인 필요`(권한 요청·확인 필요·실패), `상태 변화`(작업 중·검토 등),
  `완료`로 나눠 거를 수 있으며, 실제로 있는 분류만 버튼으로 표시합니다. 확인 필요 기록은 상태 변화가 많이 쌓여도 밀려나지 않게 따로 50건까지 남깁니다. 이동할 곳이 있는 행에만 `›`가 붙습니다.
- 알림·이벤트·완료는 이번 실행에만 남습니다. 작업별 토큰 기록은 `사용량`에서, 진행 중인 대화는 `홈`에서 봅니다.
- 비서 알림 기록 지우기는 `최근 활동` 오른쪽 `…` 메뉴에 있습니다.

### 연결과 진단 도구

설정창의 `연결·진단`은 `Codex`와 `Claude Code`를 같은 틀로 나란히 보여 줍니다. 도구마다
출처 색 점이 붙은 제목 아래에 현재 연결 상태, 사용 스위치, `연결 점검`이 차례로 있습니다. 끈 도구는 사용 스위치만 보입니다.
연결 상태는 연결됨(초록), 연결 안 됨(회색), 손볼 것 있음(경고), 설정을 읽을 수 없음(오류)으로
나누며, 상태 카드의 버튼은 `hook 연결하기`·`연결 복구하기`처럼 고칠 일이 있을 때만 나타납니다. 켜고 끄기는 사용 스위치로 합니다.
`연결 점검`은 두 도구 모두 `설치 감지 → 관리 hook → 최근 이벤트 수신` 순서로 시작하고, 이어서
Codex는 신뢰 승인·작업 로그 감시를, Claude Code는 한도 수신·거절·중단 감지를 보여 줍니다.
마지막 오류·로컬 기록 저장소·일정 알림은 아래 `앱 상태`에 따로 있습니다. 켜진 도구의 복구 검토와
진단 ZIP 내보내기, 원본 상태는 `고급 도구`에 있습니다. 모든 변경은 바뀌는 내용을 먼저 보여 준 뒤
`변경 적용`을 눌러야 반영됩니다.

`Codex 사용` 스위치는 이 앱의 Codex hook과 Codex 사용량을 함께 켜고 끕니다.
적용 전 변경 검토 창에서 확인하며, 취소하면 그대로 둡니다. 다른 Codex hook과 기능 설정, Claude Code는 바꾸지 않습니다.

`Claude Code 사용`을 켜면 Claude Code 사용자 설정
(`~/.claude/settings.json`, `CLAUDE_CONFIG_DIR`이 있으면 그 폴더)에 이 앱의 hook만 추가하고, 끄면
그 hook과 이 앱의 status line만 되돌립니다. 다른 설정과 hook은 그대로 두며 바꾸기 전 파일을 같은 폴더에 백업합니다.
이미 열려 있는 Claude Code 세션은 다시 시작해야 적용됩니다. CLI와 VS Code 확장 모두 같은 설정을
씁니다. 권한 거절·응답 중단은 몇 초 안에 작업 표시를 풀고, 그 밖에 신호가 끊긴 세션은
`세부 설정`의 `작업 중 표시 유지`(기본 10분)·`확인 대기 표시 유지`(기본 30분)가 지나면 표시를 풉니다.
도구가 실행 중인 동안에는 `확인 대기 표시 유지` 시간을 쓰고, 하위 에이전트가 일하는 동안에는 부모 대화도 작업 중으로 유지합니다.
Claude Code의 확인 대기는 권한 요청이므로 `권한 요청`으로 표시합니다. 승인할 때는 Claude Code가 신호를 보내지 않아,
승인한 도구가 끝날 때까지 이 표시가 남습니다.

Claude Code의 `한도 가져오기`(`Claude Code 사용`을 켜면 함께 켜짐)를 켜면 status line으로 5시간·7일 한도를 받습니다. 쓰던 status line이
없으면 앱이 두 줄짜리 기본 상태줄을 보여 주며, `세부 설정`의 `상태줄 항목`에서 보일 항목(펫 연결·IDE·모델·컨텍스트·5시간·7일),
줄·순서, 색 강조, 5시간 초기화 시각을 고릅니다. 한도는 터미널에서 실행한 Claude Code에서만 갱신되므로,
VS Code에서 쓰는 방법은 같은 곳의 `터미널에서 쓰는 방법`을 참고합니다. 도구·실행 위치별로 지원하는 범위는
[Claude Code 지원 범위](support-claude-code.md)에 있습니다.

알림 잠시 쉬기는 `꾸미기 → 말풍선`에 있습니다. 일정 알림은 수신·표시 준비만 되어 있고 외부 일정 시스템과는 아직 연결하지 않았습니다.

## 문제 해결

### 작업 상태가 나오지 않아요

`펫 + 비서` 구성인지, `연결·진단`에서 그 도구의 사용 스위치가 켜져 있는지 확인합니다.
Claude Code는 연결 전에 열려 있던 세션을 다시 시작하고 새 작업을 실행하세요.
`연결 점검`의 설치 감지·관리 hook·최근 이벤트 수신 결과에 따라 안내를 확인합니다.
Codex가 감지되지 않아도 펫 기능은 정상 동작합니다.

### Claude Code 한도가 나오지 않아요

`연결·진단`의 `Claude Code 사용`과 `한도 가져오기`가 모두 켜져 있는지 확인합니다.
지원되는 claude.ai Pro·Max 구독으로 터미널에서 Claude Code를 사용해야 하며 첫 응답 이후에 갱신됩니다.
VS Code 확장 패널만으로는 갱신되지 않습니다. [Claude Code 한도 안내](support-claude-code.md#한도)를 참고하세요.

### 펫을 클릭할 수 없어요

펫을 클릭하거나 드래그해도 뒤의 창이 눌린다면 펫이 고정된 상태입니다. 트레이 메뉴에서 `펫 고정` 체크를 끄거나,
지정한 `펫 고정 단축키`를 누르거나, 설정창 `꾸미기 → 펫 → 동작·화면`에서 `펫 고정`을 끕니다.
사용량 위젯도 같은 방법(`위젯 고정`)으로 풉니다. 자세한 내용은 [펫·위젯 고정](#펫위젯-고정)을 참고하세요.

### 펫 표시나 상태가 이상해요

- 저장된 펫이 손상되면 다음 정상 펫으로 대체됩니다.
- 모든 펫을 읽지 못하면 복구 창에서 다시 시도하거나 다른 폴더를 선택할 수 있습니다.
- 잘못 남은 작업 상태는 트레이에서 초기화할 수 있습니다.
- `dist/` 안의 개발 빌드를 일상 설치 위치로 사용하지 마세요.

설치 경고는 [설치와 실행](#설치와-실행), 설정창을 닫아도 펫이 남는 경우는 [앱 종료](#앱-종료),
업데이트·제거 시 데이터 처리는 [업데이트](#업데이트)와 [제거와 데이터](#제거와-데이터)를 확인하세요.
문제를 보고할 때는 [보안과 개인정보](../SECURITY.md)에 따라 앱·Windows 버전과 재현 절차를 정리하세요.

## 제한 사항

이전 버전의 대화 탐색·후보 분석·작업 대기열과 자동 실행은 어떤 설치 구성에서도 화면에 보이지 않고 시작하지 않습니다.
이미 저장된 작업 데이터는 지우지 않고 그대로 둡니다.

### 펫 더블클릭 동작

두 설치 구성에서 `꾸미기 → 펫 → 동작·화면 → 더블클릭 동작`을 선택합니다. 기본값은 설정창 홈이며,
모든 선택에서 손 흔들기를 유지합니다. 설정은 캐릭터 교체와 앱 재실행 후에도 유지합니다.
이전 버전에서 업데이트하면 기존 Codex 고정 동작 대신 설정창 홈이 기본값이 됩니다.

`Codex 열기`는 보던 대화를 유지하며 가장 앞에 있던 Codex 창을 복원·활성화하고, 창이 없으면
등록된 앱을 시작합니다. 새 대화를 만들거나 마지막 활동 대화를 자동으로 선택하지 않습니다.
실패하면 설정창 홈과 오류 안내를 표시하며 선택값은 유지합니다. `손 흔들기만`은 창을 열지 않습니다.
`Claude Code 열기 (VS Code)`는 Claude Code를 쓰는 VS Code의 가장 앞 창을 복원·활성화합니다. 열려 있던
Claude Code 패널과 터미널은 그대로 두며 새 대화를 만들지 않습니다. VS Code 창이 없으면 VS Code를 시작하고,
VS Code가 이전 작업 공간을 복원합니다. 정식 VS Code만 대상이며, 실패하면 설정창 홈과 오류 안내를 표시합니다.
