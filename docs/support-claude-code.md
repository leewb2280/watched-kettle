# Claude Code 지원 범위

[한국어](support-claude-code.md) · [English](support-claude-code.en.md)

펫+비서 구성이 Claude Code에서 무엇을 읽고 어떻게 보여 주는지, 실행 위치별로 어디까지 확인했는지 정리합니다.
현재 소스 버전은 **0.15.7(베타)**이며, 실측 자료의 기준은 **2026-10-04, 당시 앱 버전 0.14.0**입니다.
과거 실측은 현재 공개 설치판의 재검증을 뜻하지 않습니다.
확인 수준(실측·자동 검사·미확인)의 뜻과 공통 사항은 [지원 범위](support-scope.md)를 따릅니다.

## 요약

- 읽기 전용이다. 작업 상태·대화 제목·작업 기록·한도를 보여 줄 뿐, Claude Code에 작업을 보내거나 권한 요청에 답하지 않는다.
- 작업 상태는 Claude Code hook, 중단 감지·대화 제목·작업 기록은 대화 기록 파일, 한도는 status line에서 온다.
- 터미널 CLI(일반·VS Code 내장)와 VS Code 확장 패널은 실제로 확인했다. 한도는 터미널에서만 갱신되고, 대화 열기는 실행 위치에 따라 다르다.
- Claude 데스크톱 앱, `claude -p`, 다른 IDE는 관측하지 않았다.

## 확인한 환경

| 항목 | 내용 |
|---|---|
| 운영체제 | Windows 11 |
| Claude Code | 2.1.286(hook·대화 기록 조사), 2.1.287(status line 실측), 2.1.288(VS Code 확장 링크 처리 확인), 2.1.301(Windows hook 명령 형식, 2026-10-17) |
| 실행 위치 | 일반 터미널 CLI, VS Code 내장 터미널 CLI, VS Code 확장 패널(auto·default 모드) |
| 그보다 낮은 버전 | 검증하지 않았다. hook 등록 형식은 Claude Code 2.1.139 이상을 요구한다 |

## 연결 방법

1. Claude Code를 별도로 설치·로그인하고 Watched Kettle의 `펫 + 비서` 구성을 실행합니다.
2. 펫 우클릭 → `설정 → 연결·진단`에서 `Claude Code 사용`을 켭니다.
   설치할 때 이미 골랐다면 상태를 확인하면 됩니다. 변경 내용은 미리 보여 주며 `변경 적용`을 눌러야 반영됩니다.
3. 이미 열려 있던 Claude Code 세션을 다시 시작하고 새 작업을 실행한 뒤 `연결 점검`에서 이벤트 수신을 확인합니다.
4. `Claude Code 사용`을 켜면 같은 곳의 `한도 가져오기`도 함께 켜집니다. 한도만 끄려면 이 스위치를 끕니다.
   지원되는 claude.ai Pro·Max 구독의 터미널 세션에서 첫 응답 이후에 갱신됩니다. VS Code 확장 패널만으로는 갱신되지 않습니다.

전체 절차는 [첫 연결 확인](user-guide.md#첫-연결-확인)을 참고하세요. hook 연결과 사용량 수집은 `Claude Code 사용` 스위치 하나로 함께 켜고 끕니다([ADR 0006](decisions/0006-tool-activation-single-bundle.md)).

| 기능 | 앱이 바꾸는 것 | 켜고 끌 때 |
|---|---|---|
| Claude Code 사용(기본 꺼짐, [ADR 0006](decisions/0006-tool-activation-single-bundle.md)) | 사용자 설정(`~/.claude/settings.json`, `CLAUDE_CONFIG_DIR`)의 `hooks`에 이 앱 hook 14개를 추가하고 작업 기록·한도 수집을 켠다 | 끄면 이 앱 hook과 이 앱 status line을 되돌리고 Claude Code 파일을 더 읽지 않으며 모든 화면에서 숨긴다. 다른 설정과 hook은 그대로 두고, 바꾸기 전 파일을 같은 폴더에 백업한다. 저장된 기록은 남는다 |
| Claude Code 한도 가져오기(사용 중일 때만, `Claude Code 사용`을 켜면 함께 켜짐) | 사용자 설정의 `statusLine`을 이 앱 명령으로 바꾸고, 쓰던 status line은 앱 데이터에 보관 | 끄면 보관한 설정으로 되돌린다. 그 사이 사용자가 status line을 바꿨으면 덮어쓰지 않는다 |
| 상태줄 항목(`세부 설정` 안) | 기본 상태줄에 보일 항목·줄·순서, 색 강조, 5시간 초기화 시각 | 쓰던 status line이 있으면 그 출력만 그대로 보여 주므로 적용되지 않는다 |

- 이미 열려 있는 Claude Code 세션은 다시 시작해야 hook이 적용된다. CLI와 VS Code 확장이 같은 사용자 설정을 쓴다.
- 사용자 설정이 깨져 있으면(`invalid`) 덮어쓰지 않는다. `disableAllHooks`와 관리 정책 `allowManagedHooksOnly`가 켜져 있으면 hook은 설치하지 않고 상태만 보여 준다. 이때도 사용 스위치는 켜지며 활동 표시가 제한된다고 안내한다.
- 사용을 끈 동안 남은 hook이 보내는 이벤트는 앱이 버린다. 꺼진 동안에는 `~/.claude` 폴더가 있는지만 본다.
- 앱 제거 도구(`--remove-managed-hook`)는 Codex와 Claude Code의 관리 hook·status line을 함께 되돌린다.
- Windows에서 Claude Code는 명령 문자열을 Git Bash로, Git Bash가 없으면 PowerShell로 실행한다. 그래서 hook 14개는 셸을 거치지 않는 exec 형식(`command`에 실행 파일, `args`에 인자)으로 등록한다.
  status line에는 이 형식이 없다. 실행 경로가 일반 문자(영숫자·한글·`/ : . _ -`)로만 이뤄지면 따옴표 없는 경로를, 아니면 `powershell.exe -EncodedCommand` 호출을 쓴다. 두 셸이 같은 명령으로 실행한다.
  이전의 Git Bash 전용 문자열 항목은 `drifted`로 보이며 `복구`하면 새 형식으로 바뀐다.

## 실행 위치별 지원

| 기능 | 일반 터미널 CLI | VS Code 내장 터미널 CLI | VS Code 확장 패널 | `claude -p` | 데스크톱 앱·다른 IDE |
|---|---|---|---|---|---|
| 작업 중·확인 대기·완료 | 실측 | 실측 | 실측 | 미확인(hook 실행만 관측) | 미확인 |
| 중단·권한 거절 감지 | 실측 | 실측 | 실측 | 미확인 | 미확인 |
| 백그라운드 작업이 남은 완료와 그 뒤 완료 | 자동 검사 | 자동 검사 | 자동 검사 | 미확인 | 미확인 |
| 대화 제목 | 실측 | 실측 | 실측 | 미확인 | 미확인 |
| 말풍선 제목을 눌렀을 때 | 활동 목록 | 그 폴더의 VS Code 창(실측) | 패널에서 그 대화(미확인) | 활동 목록 | 활동 목록 |
| 5시간·7일 한도 | 실측 | 실측 | 갱신되지 않음(실측) | 미확인 | 미확인 |
| 작업 기록(턴별 토큰) | 실측 | 실측 | 실측 | 미확인 | 미확인 |

VS Code 확장의 터미널 모드(`claudeCode.useTerminal`)는 CLI로 실행되므로 VS Code 내장 터미널 CLI와 같다(한도 실측).

## 보여 주는 것

### 작업 상태

| Claude Code hook | 펫·말풍선 |
|---|---|
| `UserPromptSubmit`, `PreToolUse`, `PostToolUse` | 작업 중 |
| `PermissionRequest`, `Notification`(`permission_prompt`만) | 확인 대기(말풍선·설정창·트레이 표시는 `권한 요청`). 같은 세션의 다음 도구 이벤트가 오면 해제. 승인할 때는 hook이 오지 않으므로 승인한 도구가 끝날 때까지 남는다 |
| `Stop` | 완료. 백그라운드 명령·하위 에이전트가 실행 중이면 배지가 `완료 · 백그라운드 N개`(펫 알림은 일반 완료와 같음). 결과를 읽는 다음 턴이 오면 작업 중, 그 턴의 `Stop`에서 다시 완료. 감시용 작업(`monitor`, MCP 작업)은 세지 않음 |
| `PostToolUseFailure` | 작업 중 유지. `is_interrupt=true`면 중단 |
| `StopFailure` | 실패(관측하지 못함) |
| `PreCompact`·`PostCompact` | 작업 중인 턴에서만 압축 중. 턴 사이의 수동 `/compact`는 `Stop`이 오지 않으므로 펫 상태를 바꾸지 않는다 |
| `SubagentStart`·`SubagentStop` | 하위 에이전트로 따로 집계. 이름 없는 내부 에이전트는 버림 |
| `SessionEnd` | 세션 정리 |

### 말풍선 카드

- 카드 이름은 작업 폴더가 git 저장소 안이면 주 저장소 폴더 이름(워크트리·하위 폴더에서 연 세션 포함), 아니면 작업 폴더 이름이다. hook 브리지가 `.git`과 워크트리의 `commondir`로 판단하고, 홈 폴더나 드라이브 루트의 저장소는 그 아래 폴더를 묶지 않는다. 세션의 첫 이벤트에서 받은 프로젝트로 고정한다. 사용량 기록의 프로젝트도 같은 기준이며, 대화 하나의 모든 턴을 그 대화의 가장 이른 턴의 프로젝트로 묶는다. 대화 도중 다른 폴더로 옮겨 가도 나뉘지 않고, 이 기준 전에 따로 저장된 워크트리 기록도 대화를 시작한 프로젝트로 합쳐진다. 워크트리에서 시작한 대화를 이 기준 전에 기록했다면 그 대화만 따로 남는다. 행 제목은 대화 제목(사용자가 붙인 이름 우선, 없으면 자동 제목, 둘 다 없으면 `Claude Code 대화`)이다.
- 같은 폴더를 Codex와 함께 써도 카드는 출처별로 따로 둔다. Codex와 Claude Code를 둘 다 쓸 때만 머리글에 출처 색 점(Claude Code 주황)을 붙인다.
- 펫 아래 활동 문구와 트레이 상태에 작업 중인 출처 이름을 붙인다.
- 사용량 → 기록의 프로젝트 묶음은 0.15.7부터 대화를 시작한 작업 폴더의 프로젝트를 따른다. 대화 도중 워크트리 등으로 폴더를 옮겨도 같은 대화가 다른 프로젝트로 나뉘지 않으며, 이미 저장된 기록도 같은 기준으로 합쳐 보여 준다.

### 대화 열기

| 실행 위치 | 동작 | 버튼 |
|---|---|---|
| VS Code 확장 패널 | `vscode://anthropic.claude-code/open?session=<ID>`로 해당 대화 열기를 시도한다. 실제 클릭 동작은 미확인 | 대화 열기 |
| VS Code 내장 터미널 CLI | 대화 기록에서 작업 폴더를 읽어 그 폴더의 VS Code 창을 앞으로 가져온다 | 창 열기 |
| 그 밖 | 설정창 활동 목록을 연다 | 목록 보기 |

- 실행 위치는 hook 환경의 `CLAUDE_CODE_ENTRYPOINT`(`cli`·`claude-vscode`)와 `TERM_PROGRAM=vscode`로 판단한다.
- 열려 있는 CLI 세션은 패널에서 다시 열지 않는다. 같은 세션을 두 프로세스가 쓰게 되기 때문이다.
- 세션 링크가 실패하면 폴더 창, 그것도 실패하면 목록으로 물러나며 이유를 포인터 옆에 알린다.

### 한도

- status line 입력의 `rate_limits`에서 5시간·7일 사용률과 초기화 시각만 받는다. claude.ai Pro·Max 구독에서, 세션의 첫 응답 이후에만 들어온다.
- 사용량 현황·홈·위젯·트레이에 표시하고, 같은 초기화 구간에서 70·90·100%를 처음 넘으면 알린다. 앱을 다시 켠 뒤 첫 값은 알리지 않는다.
- 초기화 시각이 지난 값은 현재 값처럼 보이지 않게 뺀다. 한도 표본은 Claude Code 계정별로 8일 보관한다.
- 쓰던 status line이 없으면 앱이 두 줄짜리 기본 상태줄(연결·모델 / 컨텍스트·5시간·7일)을 보여 준다. 이 문구는 화면에만 출력하고 앱으로는 한도 숫자만 보낸다.

### 작업 기록

- 대화 기록 파일에서 턴별 토큰을 모은다. 앱이 꺼져 있던 동안의 작업도 90일 안에서 가져온다.
- 계정이 아니라 이 기기 기준이다(대화 기록에 계정이 없다). 한도 표본만 계정별이다.
- 결과는 완료·중단·진행 중으로 나눈다. 실패는 대화 기록만으로 구분하지 않는다. 비용은 공식 값이 없어 표시하지 않는다.
- 사용량 현황의 `추이`(Claude Code 선택)는 같은 턴 기록으로 오늘 시간대별·일별 토큰을 그린다(이 기기 기준, 끝난 시간 기준). 한도 선은 status line 표본으로 그리므로 터미널에서 쓰지 않은 시간은 비어 있다.
- 기록 지우기는 앱의 기록만 지우고 Claude Code의 대화 기록 파일은 건드리지 않는다.

## hook이 오지 않는 경우

| 경우 | 처리 |
|---|---|
| 응답 중 중단, 권한 거절 | 작업 중인 세션의 대화 기록에 hook 없는 사용자 줄이 생기면 2초 뒤 중단으로 처리(1초마다 확인) |
| 백그라운드 명령 결과를 읽는 턴(`UserPromptSubmit`이 없을 수 있음) | 앞 턴은 이미 완료. `UserPromptSubmit` 또는 첫 도구 이벤트가 새 턴을 열고 그 턴의 `Stop`에서 다시 완료. 결과 알림 줄은 중단으로 보지 않음 |
| 감시용 백그라운드 작업(예: 실시간 구독)이 세션 내내 실행 중 | 완료를 미루는 작업으로 보지 않음. `Stop`의 작업 종류와 상태만 읽음 |
| 끝나지 않는 백그라운드 명령(예: 개발 서버, 소스 실행 앱) | 턴이 끝날 때 `완료 · 백그라운드 N개`로 알리고 일반 완료처럼 사라짐 |
| VS Code 패널 닫기(`SessionEnd` 없음) | 무활동 만료: 작업 중 10분, 확인 대기·도구 실행 중 30분(`연결·진단`에서 변경) |
| 하위 에이전트가 오래 일함(부모 세션은 조용함) | 하위 에이전트 이벤트가 부모의 마지막 활동 시각도 갱신해, 끝난 뒤 부모의 `Stop`으로 완료 |
| 도구 하나가 오래 실행됨(긴 빌드, MCP 도구) | 끝나지 않은 도구가 있는 동안은 확인 대기와 같은 30분 기준 |
| 작업 도중 앱 시작 | 다음 hook이 올 때까지 그 세션은 보이지 않음 |
| 앱이 꺼져 있을 때 | 이벤트는 사용자 큐(최대 512개)에 쌓이고, 다시 켰을 때 60초 넘은 이벤트는 버림. Claude Code 작업은 막히지 않음 |

## 읽는 것과 읽지 않는 것

- hook에서: 이벤트 종류, 세션·프롬프트·도구 ID, 작업 폴더 이름과 경로 해시, 실행 위치. 프롬프트·응답·명령·도구 출력·전체 경로는 앱으로 보내지 않는다.
- 대화 기록에서: 줄 종류, 대화 제목, 턴별 토큰과 모델 이름. 64KiB를 넘는 줄은 해석하지 않는다. VS Code 터미널 대화의 `창 열기`를 누를 때만 작업 폴더 경로를 읽어 VS Code에 넘기고 보관하지 않는다.
- status line에서: 5시간·7일 사용률과 초기화 시각.
- 대화 제목과 폴더 이름은 실행 중 메모리에만 두고 로그·DB에 넣지 않는다. 자세한 보관 범위는 [개인정보와 저장소](privacy-and-storage.md)에 있다.

## 하지 않는 것

- Claude Code에 작업을 보내거나 권한 요청을 대신 승인·거절하지 않는다.
- 문서화되지 않은 OAuth 사용량 API로 그래픽 패널의 한도를 읽지 않는다(사용자 로그인 토큰을 직접 써야 한다).
- 비용(USD)과 git 브랜치는 표시하지 않는다.
- VS Code 터미널의 특정 탭으로 바로 이동하지 않는다. VS Code가 바깥 링크로 터미널을 고르는 명령을 허용하지 않아, 전용 VS Code 확장 없이는 폴더 창까지만 가져온다(2026-10-04 결정).

## 형식이 바뀌면

Claude Code 업데이트로 형식이 바뀌어도 Claude Code 작업은 막지 않는다. hook 브리지는 항상 정상 종료하고 아무것도 출력하지 않는다.

- 모르는 hook 이름·알림 종류는 버린다. `prompt_id`가 없으면 턴 구분 없이 처리한다.
- payload를 해석할 수 없으면 명령 인자의 이벤트 이름과 `CLAUDE_CODE_SESSION_ID`로 최소 이벤트를 만든다.
- 대화 기록 형식이 바뀌면 중단 즉시 감지가 멈추고 무활동 만료로 해제된다.
- VS Code 확장의 대화 열기 링크와 대화 기록 줄 형식은 Claude Code가 문서화하지 않은 경로다. 바뀌면 대화 열기는 폴더 창이나 목록으로 물러난다.

## 남은 확인

- VS Code 확장 패널 대화의 `대화 열기`: 실제 클릭, VS Code 창이 여러 개일 때, VS Code 확인 창
- 백그라운드 작업이 남은 완료와 그 뒤 완료(실환경)
- `StopFailure`의 실제 발생 조건, auto 모드에서 분류기가 사용자 확인으로 넘길 때의 이벤트 순서
- Claude 데스크톱 앱, `claude -p`, 다른 IDE
- 설치판 hook 처리 시간(목표 p95 100ms)과 Codex·Claude Code 실제 동시 사용
- 현재 공개 설치판의 지원 버전 범위와 실행 위치별 재검증
