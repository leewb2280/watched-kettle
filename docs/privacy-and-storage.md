# 개인정보와 저장소

[한국어](privacy-and-storage.md) · [English](privacy-and-storage.en.md)

최종 갱신: 2026-10-19 · 0.15.7 / 스키마 v9

## 위치·내용·보관

계정 전환 확인은 새 App Server의 읽기 전용 응답을 사용한다. 인증 파일 내용이나
토큰을 펫이 직접 읽거나 복사하지 않는다. 화면에는 `a***@example.com` 형태의
마스킹 이메일과 플랜만 전달하며, 원문 이메일·마스킹 이메일·플랜을 설정·사용량 DB·
로그·진단 파일에 새로 저장하지 않는다. 이메일의 메모리상 지문은 변경 감지에만
사용하고 영구 이력 키는 계속 서버 계정 식별자의 해시로 유지한다.

프로젝트 말풍선은 읽기 전용 App Server에서 프로젝트·대화 메타데이터를 별도 작업
스레드로 조회합니다. 대화 원문은 요청하지 않으며 프로젝트명·대화/부모 ID·작업 경로와
행동 대상은 메모리에만 둡니다. 기존 hook 이벤트·SQLite·진단 저장에는 이 필드를 추가하지
않습니다. 프로젝트 이벤트(상태 변화 20건·확인 필요 50건), 최근 완료 100건, 일반 알림 50건과 확인 상태도 메모리에서만 관리하며
연결/계정 세대 변경 또는 종료 시 정리합니다. 사용자 일정관리 시스템은 아직 미연결입니다.
설정창 `알림 기록` 화면은 이 일시적 행만 보여 주며 종료 시 사라진다고 고지합니다. DB 기반 작업별 토큰 기록은 `사용량` 화면에서 봅니다. 앱 전체 제거 때 사용자는 데이터 유지(대화형 기본값), 기록만 삭제, 모두 삭제 중 하나를 선택합니다. 무인 제거는 데이터를 유지합니다. 비서 구성만 해제할 때는 DB 기록을 유지합니다.

사용자 데이터 루트는 `%LOCALAPPDATA%\WatchedKettle`다. 이전 이름(Codex Desktop Pets)의 `%LOCALAPPDATA%\CodexDesktopPets`가 있으면 첫 실행 때 폴더째 옮기며, 다른 프로세스가 잡고 있으면 그 실행에서는 이전 폴더를 그대로 쓰고 다음 실행에서 다시 옮긴다([ADR 0005](decisions/0005-product-name-watched-kettle.md)). 아래 DB 파일명은 호환성을 위해 유지하며 내부 스키마는 v3다.

펫·위젯·설정창의 위치와 크기를 포함한 모든 설정·기록은 이 데이터 루트에만 저장되며 설치 폴더나 배포 번들에 쓰지 않는다.
같은 PC에서는 소스 실행과 패키지 실행이 이 폴더를 함께 쓰므로 패키지도 마지막으로 옮긴 위치에서 켜진다. 번들 빌드는
`scripts.release_artifacts inspect`로 설정·DB·로그·런타임 파일과 빌드 PC 경로(실행 파일 안의 Python 코드 포함)가 없는지 검사하고, 있으면 ZIP을 만들지 않는다.

보관량 정리는 저장 후와 앱 실행 중 정기 유지보수에서 수행한다. 조회는 만료된 새 기록을 표시하지 않지만 앱이 꺼진 동안 물리적 삭제가 실행되지는 않는다. 이전 기록은 새로운 정상 기록의 보관량 정리 대상에서 제외한다.

작업 기록의 500건 초과 자동 삭제는 하지 않는다. 보존 기간과 화면 조회량은 분리하며, 검색·정렬은 현재 계정의 보존된 전체 기록에 적용한 뒤 최대 100건만 전달한다. 과거 정책으로 이미 삭제된 DB 행을 원본 로그만으로 새로 생성하지는 않는다. 미측정 기록 복구는 화면 페이지와 무관하게 DB에서 200건씩 읽고, 한 묶음의 검사가 끝나면 다음 묶음으로 이동한다. 계정 전환·기록 삭제 시 페이지 조회와 복구 순회를 취소한다.

펫 가져오기의 준비 이미지·임시 식별자는 최대 한 건·10분간 메모리에만 두고 취소·재선택·
설정창 숨김·연결 종료 시 폐기합니다. 추가 시 데이터 루트의 임시 폴더에 패키지를 완성한 뒤
`pets/`에 게시하고 정상 완료·실패 시 임시 폴더를 정리합니다. 강제 종료로 남은 `pet-import-*`
임시 폴더는 펫 목록에서 제외됩니다. 원본 다운로드 파일은 변경하지 않습니다.

## 펫 관리와 휴지통

앱 데이터 폴더의 `pet-trash/<임시 ID>/`에 사용자 펫 패키지와 `record.json`을 보관합니다.
기록에는 펫 ID·이름·원래 폴더 이름·삭제 시각·표시 여부·이전 순서·작업 상태를 저장합니다.
전체 원본 경로 대신 사용자 펫 폴더 안의 폴더 이름을 사용하며 이 기록은 활동·사용량 DB와 분리합니다.
개별 꾸미기 설정은 복원할 수 있도록 유지하고, 사용자가 영구 삭제를 확정할 때 해당 펫 설정도 지웁니다.
휴지통은 자동 만료하지 않습니다. 앱 제거의 데이터 유지·기록만 삭제는 사용자 펫과 휴지통을 남기며 모두 삭제는 함께 지웁니다.

이동·복원·삭제 의도를 먼저 기록하고 시작 시 미완료 파일 작업을 복구합니다. 읽을 수 없거나 충돌하는 데이터는 보존합니다.
일괄 처리의 진행·마지막 결과는 현재 실행의 메모리에만 두며, 재시작 시 미처리 대상을 자동 실행하지 않습니다.
파일 조작은 사용자 펫 폴더와 앱 전용 휴지통으로 제한하고 외부 연결 폴더와 기본 제공 펫은 보호합니다.
일반 로그·진단에 이 관리 기록의 이름·경로·원문을 추가하지 않습니다.

## 사용량 계정과 측정

프로젝트별 사용량 화면은 먼저 확인된 계정의 DB 분류를 복원하고, 읽기 전용 `project/list`·`thread/list`·`thread/read(includeTurns=false)`와 데스크톱의 프로젝트 연결 정보로 갱신합니다. 계정·대화·프로젝트의 해시 관계와 확인 시각·분류 근거만 저장합니다. 실제 프로젝트명과 대화 제목은 현재 계정·연결 세대의 메모리에만 두며 프롬프트 미리보기를 제목으로 사용하지 않습니다. 재시작 직후 분류는 복원되지만 이름·제목은 다시 조회합니다. 계정 초기화·종료 시 이름 캐시를 비우고 계정별 분류는 유지하며, 사용량 기록 삭제 시 해당 분류도 지웁니다. 프로젝트·대화 요약은 전체 보존 기록을 집계하되 화면에는 프로젝트 100건, 선택된 프로젝트의 대화 100건, 선택된 대화의 작업 100건만 전달합니다. 프로젝트 정렬 방식과 사용자 지정 순서는 계정 해시별 QSettings에 프로젝트 키만 저장합니다. 이름·제목은 이 설정에 포함하지 않으며 Codex 자체의 프로젝트 순서는 변경하지 않습니다.

- 영구 계정 키는 App Server가 제공한 `accountId`의 해시다. 이메일은 현재 연결에서 계정 변경을 감지하는 데만 쓰며 저장 키로 사용하지 않는다.
- 계정 ID가 없으면 한도는 표시할 수 있지만 영구 이력 조회·저장·삭제를 보류한다. 로그아웃·계정 변경·재연결에서 이전 관측과 지연 응답을 분리한다.
- 해시는 원본 식별자 노출을 줄이는 가명 식별자이며 완전 익명화를 보장하지 않는다.
- 작업별 토큰은 이 기기의 Codex 로그에서 작업 시작·완료와 토큰 누적값을 확인해 계산한다. 누적값 역전, 로그 누락, 소유 관계가 불명확한 기록은 측정 불가로 남긴다. 대화 제목·프롬프트·로그 원문은 저장하지 않는다. 작업별 크레딧·USD는 로그에서 제공되지 않으므로 임의로 만들지 않는다.
- 분할 로그는 헤더 소유자와 이전 파일의 바이트·순번 경계를 검증해 연결한다. 복구는 현재 계정의 기존 대화·작업 해시와 일치하는 측정 불가 행만 갱신하며, 계정 귀속이 모호하면 보강하지 않는다. 진행 상태는 메모리에만 유지하고 마지막 검사 사유와 최초 수집 사유는 기존 품질 사유 필드에 함께 저장한다. 원본 로그와 DB 스키마는 변경하지 않는다. 계정 전환·로그아웃·기록 삭제는 복구와 캐시를 취소하며 과거 활동 이벤트를 다시 전달하지 않는다.
- 복구 변경은 계정·실행 세대를 확인한 뒤 최대 200ms 간격으로 묶어 저장한다. 같은 판정은 다시 쓰지 않으며, 검증된 로그 경계·누적값·작업 식별자의 메모리 캐시는 최대 1,024개 경계로 제한한다. 새 파일 탐색과 본문 검사를 분리해 관련 없는 대화 로그를 반복 파싱하지 않는다. 계정 검증 중 보류된 변경만 해당 세대에 재적용하며 계정 전환·기록 삭제 시 대기 묶음도 비운다.
- 원문 계정·대화·턴 ID, 프롬프트, Codex 대화 제목, 명령, transcript와 도구 출력은 사용량 DB·로그·진단에 저장하지 않는다. 진단 ZIP에는 DB 본문을 포함하지 않는다.
- `app.log`는 schema 1 JSONL이다. 각 행에는 UTC 시각, level, run_id, component, event가 포함되며
  상태·오류 코드·소요 시간 같은 제한된 진단 필드만 추가된다. 인증 파일, 토큰, 이메일, 계정 ID,
  전체 경로, App Server 응답 본문과 stderr는 저장하지 않는다.
- 사용자 일정 알림 제목은 표시와 임시 전달 큐에 포함될 수 있다. 사용자 펫·장식 metadata와 QSettings의 경로 설정은 사용량 DB의 원문 비저장 정책과 구분한다.

## 장애와 삭제

지원하지 않는 미래 DB는 변경하지 않는다. 손상 DB는 원본 보존에 성공한 경우에만 새 DB를 만들며, 안전하게 복구할 수 없는 부분 생성 DB는 보존하고 메모리 모드로 동작한다. 이 모드에서는 재시작 후 기록이 유지되지 않는다.

사용량 화면의 기록 삭제는 확인된 현재 계정만 대상으로 하고, 저장소 처리 성공 후 완료를 표시한다. 다른 계정 자료·별도 백업·사용자 펫을 함께 삭제하지 않는다.

앱 전체 제거는 관리 hook과 이 앱의 자동 시작 등록을 해제한다. 대화형 제거의 기본값인 `데이터 유지`와 무인 제거는 사용자 데이터를 보존한다. `기록만 삭제`(비서 기록 파일이 있을 때만 표시)는 비서 DB·부속 파일·백업·이전 사용량 파일과 앱 로그·임시 이벤트를 지우고 `settings.ini`, 사용자 펫·장식은 보존한다. `모두 삭제`는 사용자 데이터 폴더와 이전 QSettings도 지운다. 제거기는 지우기 전에 실행 중인 앱을 종료하고, 다른 프로그램이 데이터 파일을 열고 있으면 아무것도 지우지 않고 멈춘다. 사용자 데이터가 없으면 데이터 선택 창을 띄우지 않는다. Codex 본체의 대화·설정과 다른 hook은 삭제하지 않는다. 별도 프로젝트 런타임 폴더는 앱 데이터 폴더 밖에 있으므로 자동으로 순회·삭제하지 않는다.

## 읽기 범위와 기능 제어

JSONL 상태 관찰·사용량 비서는 로컬 Codex와 연결하며 설정창의 `연결·진단`·`사용량`에서 상태와 사용량 기능을 확인하고 끌 수 있다. Codex home은 `CODEX_HOME`이 지정되면 해당 위치, 없으면 `~/.codex`를 따른다. 기존 외부 hook 설정은 경로 변경만으로 자동 이전하지 않는다.

Claude Code 연동(13단계)은 hook 이벤트에서 상태 판단에 필요한 식별자와 종류만 받는다. Claude Code는 권한 거절·응답 중단 때 hook을 보내지 않으므로, 작업 중인 세션에 한해 대화 기록(`CLAUDE_CONFIG_DIR` 또는 `~/.claude`의 `projects/*/<세션 ID>.jsonl`)에 새로 추가된 줄의 종류(항목 type, 내용 항목 type, 메타·압축 표시)만 확인한다. 64KiB를 넘는 줄은 해석하지 않는다. 프롬프트·응답·도구 결과 원문은 메모리에 보관하지 않고 로그·DB·진단에 남기지 않으며, 턴이 끝나면 감시를 멈춘다.
hook 이벤트는 세션의 실행 위치(`vscode-panel`·`vscode-terminal`·`terminal` 중 하나)도 함께 보내며 앱은 이를 실행 중 메모리에만 둔다. VS Code 터미널에서 실행 중인 대화의 `창 열기`를 누를 때만 그 세션의 대화 기록 끝부분(64KiB)에서 작업 폴더 경로를 읽어 VS Code에 넘기는 주소를 만들고, 경로는 보관하거나 로그에 남기지 않는다.

대화 읽기는 사용자가 명시적으로 켠 뒤 시작한다. 프로젝트마다 최근 대화 10개에서 명시적 계획을 읽고, 과거 대화는 사용자가 선택할 때 읽는다. 원문은 외부 분석 모델로 전송하지 않는다. 지원되는 저장소에서는 원문을 페이지별로 처리하고 후보·해시만 남긴다. 미등록 후보는 최근 범위와 현재 과거 페이지에서 벗어나면 메모리에서 제거한다. 사용자가 저장한 작업은 별도로 유지한다.

스키마 v6의 작업 원장에 v7의 후보 연결 키와 암호화 완료 요약을 추가한다. 지시문·출처·제목·경로는 사용자별 DPAPI로 암호화하고 계정별로 접근을 분리한다. 후보 연결·제외 키에는 비밀 키를 사용한 HMAC을 사용한다. 완료 요약에는 제목·대상 대화·프로젝트·완료 시각·판정과 조건 설명만 남기며 전체 지시문은 삭제한다. 완료 기록은 30일·500개, 제외 기록은 30일로 정리한다. 진행·복구 대상은 이 정리로 삭제하지 않는다.

v7 이전에는 일관된 DB 백업을 만든다. 미실행 대기 작업은 원본 버전 계산 변경에 따라 재검토할 초안으로 옮기며 원래 지시문은 보존한다. 이전 버전에서 이미 삭제한 완료 내용은 복원하지 않는다. 오래된 제외 기록은 프로젝트 정보가 없을 수 있어 `모든 프로젝트의 제외 후보 복원`에서 해제한다.

자동 실행에는 별도 Desktop 공유 연결을 사용한다. 계정·실행 관측·소유권·승인 전달 검수가 끝나기 전에는 실행하지 않는다. 별도 읽기 서버의 목록이나 로그 추정치를 Desktop 전체 실행 상태로 취급하지 않는다.

## 네트워크와 설치기

이 앱은 자체 서버가 없고 사용 데이터를 외부로 보내지 않는다. Codex 사용량·계정 확인은 로컬 Codex App Server 프로세스에
표준 입출력으로 요청한다. 그 프로세스가 사용자의 Codex 로그인으로 외부와 통신하는 범위는 Codex가 정한다.

앱이 직접 인터넷에 연결하는 경우는 업데이트 확인과 펫 가져오기의 설치 명령어 두 가지다. 업데이트는 설정창
`앱 설정 → 버전과 업데이트`에서 `업데이트 확인`을 누를 때,
그리고 설치판에서 `업데이트 자동 확인`(기본 켜짐)이 켜져 있으면 하루에 한 번(앱을 켜고 1분 뒤부터, 마지막으로 답을 받은 뒤
24시간이 지났을 때. 실패하면 3시간 뒤 다시) 확인한다. 소스·ZIP 실행은 스스로 확인하지 않는다. 확인할 때마다 빌드에
포함된 GitHub Releases 주소(`api.github.com`)로 `User-Agent: WatchedKettle-update-check` 요청을 한 번 보내며 계정·기기·사용
기록은 보내지 않는다. 자동 확인은 마지막으로 답을 받은 시각과 알린 버전만 설정(`[updates]`)에 남기고(업데이트 뒤 안내 말풍선을 한 번만 보이려고 마지막으로 실행한 버전도 같은 곳에 둔다), 새 버전을 찾아도
알리기만 하며 내려받지 않는다. 일반 HTTPS 요청처럼 GitHub은 접속 IP 주소를 받는다. 응답에서는 최신 버전 태그와 Release 페이지 주소만
확인하고 저장하지 않는다. Release가 아직 없으면 GitHub이 404를 돌려주고 그 사실만 안내한다. `변경 사항 보기`를 누르면
브라우저로 Release 페이지를 연다. 0.15.5부터 확인하는 곳은 업데이트 파일만 올리는 공개 저장소
`leewb2280/watched-kettle-updates`의 Release이고, `변경 사항 보기`는 본 저장소 `leewb2280/watched-kettle`의 같은 버전 Release를
연다([ADR 0008](decisions/0008-update-repository.md)). 0.15.4까지의 설치판은 본 저장소의 Release를 확인한다. 두 저장소 모두 같은
GitHub 주소를 쓰므로 보내는 정보와 연결하는 서버는 같다.

새 버전이 있을 때 `업데이트`를 누르면 그때만 같은 Release의 설치 파일과 확인용 `.sha256` 파일을 `github.com`과 GitHub 첨부
파일 서버(`objects.githubusercontent.com`, `release-assets.githubusercontent.com`)에서 같은 `User-Agent`로 내려받는다. 다른
정보는 보내지 않는다. 설치 파일은 `%LOCALAPPDATA%\WatchedKettle\updates`에 받는다. 체크섬이 맞지 않거나 취소·실패하면
바로 지운다. 설치를 시작한 파일은 다음 실행 때 지우고, 제거할 때는 `데이터 유지`를 골라도 이 폴더를 지운다.
설치판은 확인할 때 같은 Release의 업데이트 색인(`WatchedKettle-<버전>-update.json`과 `.sha256`)도 같은 방식으로 받고,
가능하면 설치 파일 대신 바뀐 파일만 담은 zip을 받는다([ADR 0007](decisions/0007-partial-updates.md)). zip은 같은 `updates`
폴더에 받고, 새 프로그램 파일은 설치 폴더의 `runtime\<구성>.next`에 준비한다(바뀌지 않은 파일은 하드링크라 디스크를 거의 더
쓰지 않는다). 앱이 종료되면 실행기가 폴더를 바꾸고, 이전 프로그램 폴더(`runtime\<구성>.old`)와 받은 zip은 다음 실행 때
지운다. 이 과정에서 보내는 정보는 설치 파일을 받을 때와 같다. 개발용 시험
빌드(`build_windows.ps1 -UpdateTestPort`)만 GitHub 대신 같은 PC의 `127.0.0.1` 시험 서버에 같은 요청을 보내며, 공개 배포
빌드에는 이 주소가 들어가지 않는다.

펫 가져오기의 `설치 명령어`에서 `다운로드`를 누를 때만, 붙여 넣은 명령의 펫 ID로 공개 펫 서비스에서 펫을 받는다.
CodexPetDB는 `codexpetdb.com`(목록)과 `cdn.codexpetdb.com`(ZIP)을, Pets Codex는 `api.github.com`(공개 저장소의 최신 커밋)과
`raw.githubusercontent.com`(매니페스트·이미지)을 쓴다. 이 네 HTTPS 주소만 허용하고 리디렉션을 따르지 않으며, 펫 ID가 담긴
주소와 `User-Agent: WatchedKettle-PetImport` 외에 계정·기기·사용 기록은 보내지 않는다. 일반 HTTPS 요청처럼 각 서비스는 접속 IP
주소를 받는다. 명령은 실행하지 않는다. 받은 ZIP은 검증하는 동안만 시스템 임시 폴더에 두고 지우며, 검증한 자산만 사용자 펫 폴더에
새 패키지로 저장한다. 자동 확인·재시도는 하지 않는다. `파일·폴더`와 `Codex에 설치된 펫` 입력은 네트워크를 쓰지 않는다.
설정창 `정보`의 저장소·패치노트 링크는 앱이 아니라 기본 브라우저가 연다.

Windows 설치기는 사용자가 고른 도구에 한해 앱 화면을 띄우지 않는 `--configure-integrations` 모드로 이 앱의 관리 hook을
설치·제거하고, 그 도구의 사용 스위치를 `settings.ini`에 저장한다. 고르지 않은 도구와 다른 hook·도구 설정은 바꾸지 않는다.

## 사용하지 않는 도구

Codex와 Claude Code는 도구마다 사용 스위치가 있다([ADR 0006](decisions/0006-tool-activation-single-bundle.md)). 꺼진 도구의
파일은 읽지 않는다. Codex를 끄면 로그(`sessions`·`archived_sessions`) tail, `auth.json` 확인과 `codex app-server` 실행,
`.codex-global-state.json` 읽기, 진단의 hook·`config.toml` 읽기가 멈춘다. Claude Code를 끄면 대화 기록 읽기와
`settings.json` 상태 확인이 멈춘다. 연결·진단 화면은 그 도구의 폴더가 있는지만 본다. 끄는 순간 그 도구의 진행 중
카드와 펫 상태를 지우고, 이 앱이 추가한 hook이 남아 있어도 그 이벤트를 버린다. 이미 저장한 기록은 지우지 않는다.

## 기기 관측 기록 분리

JSONL `sessions`와 `archived_sessions`의 숫자·상태만 읽는다. 로컬 로그에는 계정 소유권 증명이 없으므로 토큰/한도 관측은 **이 기기** 기록이다. 여러 Codex 계정의 활동을 포함할 수 있다. 계정 한도 그래프·알림은 App Server 응답만 사용하며 기기 수치를 합산하지 않는다.

스키마 v5의 `device_token_events`는 이벤트·세션 해시, UTC 시각과 양의 토큰 차이만, `device_quota_samples`는 이벤트 해시·한도 구간·UTC 시각·사용률·재설정 시각만 저장한다. 두 테이블에 계정 열은 없다. 각 테이블은 8일/20,000건 한도이며 저장 후와 유지보수에서 정리하고 읽을 때도 만료분을 제외한다. 원래 로그는 수정하거나 지우지 않는다.

v4 로컬 토큰과 한도 샘플은 소유권/측정 신뢰를 확인할 수 없는 이전 기록으로 보존한다. 계정 화면/현재 집계에 자동 승격하지 않고 기기 이전 기록에서 최대 500건을 열람한다. 이전 기록은 자동 보관량 정리 대상에서 제외한다. 새로운 계정 한도 샘플은 `source=app_server`, v4 한도는 `source=legacy_unverified`로 구분한다.

`현재 계정 기록 지우기`는 확인된 계정의 서버 관측·작업 이력만 삭제한다. `기기 관측 기록 지우기`는 새 기기 기록과 위 v4 이전 기록을 함께 삭제하며 계정 이력은 보존한다. 기기 clear watermark는 재수입 방지 시각이며 이전 계정별 watermark의 최댓값으로 이전한다. 별도 DB/WAL/백업·원본 JSONL·QSettings·hook은 이 삭제로 제거되지 않는다. 기능을 끄면 새 관측 저장을 중단하고 기존 기록은 유지한다.

이전 전 일관된 백업을 만들며 DDL과 버전 기록은 한 트랜잭션으로 처리한다. 미래 버전 DB는 원본을 변경하지 않는 제한 모드로 연다. 백업은 자동 삭제하지 않는다.
