# Watched Kettle 0.15.7

[한국어](v0.15.7.md) · [English](v0.15.7.en.md)

Released 2026-10-19. This release adds the pet double-click action and settings home, Open Claude Code, pet and widget locks (click-through) with global shortcuts, expanded pet import (ZIP, folder, install command, pets installed in Codex), a tidier pet manager, the About page and Notification history in the settings window, and improvements to Codex task status and usage history.

**You only need `WatchedKettle-0.15.7-public-unsigned-setup.exe`.**

> Unofficial project. Not made or endorsed by, or affiliated with, OpenAI or Anthropic.

## Installing and updating

- **New installation:** download `WatchedKettle-0.15.7-public-unsigned-setup.exe` and its `.exe.sha256` attached to the Release. Compare the hash with `Get-FileHash .\WatchedKettle-0.15.7-public-unsigned-setup.exe` in PowerShell, then run it.
- **Updating from 0.15.6 or 0.15.5:** click `App settings → Version & updates → Check for updates → Update`. Only the changed files are downloaded when possible.
- **Updating from 0.15.4 or 0.15.3:** the same steps download the full installer, because those versions read this repository's Releases, and this repository carries only the combined installer.
- Your edition, tools, settings, custom pets and history are kept. The installer is unsigned, so Windows SmartScreen may show a warning.
- In Pet + assistant, the history database is converted once to a new format (schema v9, adding Codex usage project classification) on the first start, with a backup (`.bak`) made in the same folder first. If you go back to 0.15.6 or earlier after running 0.15.7, the earlier version does not open the new database, so assistant history is not shown. Pet features keep working.

## Pet double-click and settings home

- Double-clicking the pet now waves and opens the **settings home**. This replaces the former fixed "Open Codex" action as the default.
- In `Customize → Pet → Behavior → Double-click action`, choose `Settings home`, `Open Codex`, `Open Claude Code (VS Code)` or `Wave only`. Every choice keeps the wave.
- `Open Codex` and `Open Claude Code (VS Code)` restore and activate the frontmost Codex or VS Code window without creating a new conversation. If there is no window, they start the app; if that fails, the settings home opens with an error message.
- The Pet only edition also gets a Home page in the settings window, with direct links to Pet, Bubbles and App settings.

## Pet and widget locks

- When the pet or the usage widget covers another app, **lock** it so that clicks pass through to the window behind. The pet and the widget are locked separately.
- Turn a lock on from the pet's right-click menu, the tray menu or the settings window, and turn it off from the tray menu, the settings window or a shortcut.
- Set the combination you want (Ctrl or Alt with a letter, digit or F1–F24) in `Pet lock shortcut` and `Widget lock shortcut` to toggle the lock from any app. No shortcut is set at first, and the two shortcuts cannot share a combination.
- In Pet + assistant, you can choose `Let clicks pass through bubbles with buttons too`. It is off by default, so bubble buttons stay clickable.
- A locked pet stays visible, moves and follows the pointer with its gaze. See the [user guide](../user-guide.en.md#locking-the-pet-and-widget) for details.

## Notification history in settings

- `Activity history` in the settings window is now **`Notification history`**, the place to review notifications that passed by as bubbles and the task events of the current run. Notification settings stay on the `Bubbles` and `Usage` pages as before.
- `Unread notifications` expands with `Show N more` when there are more than 5, and `Mark all as read` marks them all as read at once. Notification bubbles that were waiting are dismissed too.
- `Recent activity` can be filtered by `Notifications`, `Needs attention` (permission requests, needs attention and failures), `Status changes` and `Completed`.
- Per-task token history is shown only on `Usage`, so the same task no longer appears twice. All active conversations are shown on `Home`.

## Pet manager

- The `Select` button in the pet manager moved above the list, next to `Reorder`. In the trash, it is to the right of the count and size summary. In selection mode, `Select all in current view` and `Deselect` appear in the same place.
- `Select` is available only when pets you added yourself (pets in the user pets folder) are in the list. Bundled pets cannot be deleted, only hidden.

## Importing pets

- `Customize → Pet → Import pet` accepts three kinds of input. **File or folder** accepts a pet ZIP and a pet folder containing `pet.json` in addition to PNG/WebP; **Install command** accepts an install command copied from CodexPetDB or Pets Codex; **Pets installed in Codex** accepts pets in your Codex user folder.
- Install commands are never run. The app reads only the pet ID and downloads directly from that service, so Node.js or a separate CLI is not needed. This feature connects to the internet only when you click **Download**, and sends no account or usage history.
- Supported information such as the name, description, author, size, look range, idle activities and bubble decorations is imported too. Information that is not imported (items this app does not use, bubble settings that point to decorations from another installation) is reported before registration.
- The import window previews the nine actions (and the directional poses for V2 pets). Adding a pet alone does not change the pet you are using.

## About page

- The settings window's left menu now has `About`, showing the version and edition, what's new in this version, and the licenses of the open-source components included in the app.
- The full release notes, the changelog (the list of Releases for every version), the GitHub repository, bug reports and license links open in your default browser. `Open licenses folder` opens the installation folder's `licenses` folder, which contains the full text of each license.
- The first time you start the app after an update, the pet tells you once that it was updated. If bubbles are off or snoozed at that time, the message is not shown and is not repeated later.

## Settings window and menu refinements

- The tray menu is now grouped into `Snooze notifications` · `Hide pet` · `Lock pet` · `Lock widget` and `Open home` · `View usage` · `Settings` · `Check for updates`. The Pet only edition's tray `Pet settings` is renamed `Settings` to match.
- Clicking `Check for updates` in the tray opens the version row in `App settings` and starts a check right away.
- The same action now has one name everywhere: `Bring to screen center`, `Move back beside pet`. `Idle activities`, `Walk around the screen` and `Always on top` in the pet's right-click menu now match the settings window, and the button next to the movement display is now `Move to the selected display`.
- An empty shortcut field is shown in dimmed text so it no longer looks like a button. Items already read in `Notification history` are marked `Read`.
- The Pet + assistant home's subtitle now matches what Home brings together, and the spacing of `Customize` in the Pet only edition's left menu is fixed. Fully translated official language packs no longer show a translation count.
- `Double-click action` moved from `App settings` to the `Behavior` tab of the Pet page (below the mouse reaction distance).
- Clicking a setting's name toggles the switch next to it. The information (i) icons on `Notification history` and `Connections & diagnostics` can be reached with the Tab key to show their descriptions, and screen readers read the Codex connection status dot together with the setting descriptions.

## Fixes

- Fixed Codex tasks dropping out of cards and task counts when new tool calls continued in the same task after the App Server's saved history had judged it finished. They are now shown as working again. A project card's working count now also includes tasks handling permissions.
- Codex usage history now saves its project classification, so after a restart the existing classification is shown right away and only changed conversations are checked again. Project names and conversation titles are still kept only in memory while running.
- Fixed Claude Code usage history splitting the same conversation into `Claude Code tasks` or a separate project named after the folder when the working folder (a worktree, for example) changed mid-conversation. Already saved history is also shown merged under the project where the conversation started.
