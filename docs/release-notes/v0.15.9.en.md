# Watched Kettle 0.15.9

[한국어](v0.15.9.md) · [English](v0.15.9.en.md)

Released 2026-10-20. A fix release in which Codex bubbles show task states and why a task stopped more accurately, and Claude Code completion notices and Open window are fixed.

**You only need `WatchedKettle-0.15.9-public-unsigned-setup.exe`.**

> Unofficial project. Not made or endorsed by, or affiliated with, OpenAI or Anthropic.

## Installing and updating

- **New installation:** download `WatchedKettle-0.15.9-public-unsigned-setup.exe` and its `.exe.sha256` attached to the Release. Compare the hash with `Get-FileHash .\WatchedKettle-0.15.9-public-unsigned-setup.exe` in PowerShell, then run it.
- **Updating from 0.15.8, 0.15.7 or 0.15.6:** click `App settings → Version & updates → Check for updates → Update`. Only the changed files are downloaded when possible.
- **Updating from 0.15.5:** the same steps download the update installer for your edition. Changed-file updates cover the previous three versions.
- **Updating from 0.15.4 or 0.15.3:** the same steps download the full installer, because those versions read this repository's Releases, and this repository carries only the combined installer.
- Your edition, tools, settings, custom pets and history are kept. The history database format is the same as 0.15.8 and is not converted. The installer is unsigned, so Windows SmartScreen may show a warning.

## Codex bubbles

- **Tasks stopped by the usage limit:** when a parent conversation and its subagents hit the usage limit together, a subagent's late signal could reopen the finished parent, leaving its bubble at `Checking status` for hours. A stopped conversation now shows `Usage limit` and goes away after a moment like other failures. When the time you can use Codex again is known, the badge shows it, such as `Limit · resumes at 15:20`.
- **Why a task stopped:** the badge of a task stopped by an error now names the reason (`Usage limit`, `Rate limit`, `Budget limit`, `Conversation too long` or `Server error`), and hovering over it shows an explanation. An unknown reason shows `Failed`. The card header counts conversations stopped by the usage limit. Error messages are not stored.
- **No response:** a conversation that sends no signal for a while shows `No response` instead of `Checking status`, and the bubble clears it 15 minutes after its last signal. It is not recorded as completed or failed. A parent waiting while its subagent works is not cleared.
- **Waiting and planning:** the bubble shows `Waiting for subagents` while Codex waits on subagents, `Waiting briefly` while it waits for a set time, and `Planning` in plan mode. Task counts and the pet's behavior stay the same.
- **Usage 100% notice:** the notice now reads `Codex usage limit reached` instead of `Codex remaining: 0%`.

## Claude Code

- **Completion with background work left:** when Claude Code finishes a reply while background commands (an app you started, for example) or subagents are still running, it now reports completion right away and the row shows `Complete · Background: N`. Before, the row only showed the background count and gave no completion notice until the session woke up again. When it resumes to read the results the row shows working, and it completes once more when it wraps up.
- **Open window:** `Open window` in the bubble of a Claude Code session run in a VS Code terminal opens the VS Code window of the folder where the session started, not a worktree folder the session moved into.

## Connections

- When Codex or Claude Code hooks point at another Watched Kettle install on this PC (an installed build or a source run) and that program exists, the app no longer says the connection was lost, because the installs share the same event folder and task states still arrive. `Connections & diagnostics` shows `Connected through another Watched Kettle copy` and `Switch to this copy`.
