# Watched Kettle 0.15.9

[한국어](v0.15.9.md) · [English](v0.15.9.en.md)

2026-10-20 공개. Codex 말풍선이 작업 상태와 멈춘 이유를 더 정확하게 보이고, Claude Code의 완료 알림과 창 열기를 고친 수정판입니다.

**`WatchedKettle-0.15.9-public-unsigned-setup.exe` 하나만 받으면 됩니다.**

> 비공식 프로젝트입니다. OpenAI 또는 Anthropic이 만들거나 승인한 제품이 아니며 두 회사와 관계가 없습니다.

## 설치와 업데이트

- **새 설치:** Release에 첨부한 `WatchedKettle-0.15.9-public-unsigned-setup.exe`와 `.exe.sha256`을 받습니다. PowerShell에서 `Get-FileHash .\WatchedKettle-0.15.9-public-unsigned-setup.exe`로 해시를 비교한 뒤 실행합니다.
- **0.15.8·0.15.7·0.15.6에서 업데이트:** `앱 설정 → 버전과 업데이트 → 업데이트 확인 → 업데이트`를 누릅니다. 가능하면 바뀐 파일만 받습니다.
- **0.15.5에서 업데이트:** 같은 방법으로 설치 구성에 맞는 업데이트 설치 파일을 받습니다. 바뀐 파일만 받는 업데이트는 직전 세 버전까지 지원합니다.
- **0.15.4·0.15.3에서 업데이트:** 같은 방법으로 전체 설치 파일을 받습니다. 두 버전은 이 저장소의 Release를 읽고, 이 저장소에는 통합 설치기만 올리기 때문입니다.
- 고른 설치 구성과 도구·설정·사용자 펫·기록은 유지합니다. 기록 DB 형식은 0.15.8과 같아 바뀌지 않습니다. 설치 파일은 미서명이며 Windows SmartScreen 경고가 나올 수 있습니다.

## Codex 말풍선

- **사용량 한도로 멈춘 작업:** 부모 대화와 서브에이전트가 함께 사용량 한도에 걸리면, 서브에이전트의 늦은 신호가 끝난 부모 대화를 다시 열어 말풍선이 `상태 확인 중`으로 몇 시간씩 남던 문제를 고쳤습니다. 이제 멈춘 대화는 `사용량 한도`로 보이고 다른 실패처럼 잠시 뒤 사라집니다. 다시 쓸 수 있는 시각을 알면 `한도 · 15:20 재개`처럼 함께 보여 줍니다.
- **멈춘 이유:** 오류로 멈춘 작업의 배지가 `사용량 한도`·`요청 한도`·`예산 한도`·`대화 길이 초과`·`서버 오류`로 이유를 알려 주고, 배지에 마우스를 올리면 설명이 나옵니다. 이유를 알 수 없으면 `실패`입니다. 카드 머리글에는 사용량 한도로 멈춘 대화 수를 셉니다. 오류 원문은 저장하지 않습니다.
- **응답 없음:** 한동안 신호가 오지 않는 대화는 `상태 확인 중` 대신 `응답 없음`으로 보이고, 마지막 신호 뒤 15분이 지나면 말풍선에서 정리합니다. 완료나 실패로 기록하지는 않습니다. 서브에이전트가 일하는 동안 기다리는 부모 대화는 정리하지 않습니다.
- **기다리는 중·계획 중:** Codex가 서브에이전트를 기다리면 `서브에이전트 대기`, 정해진 시간 동안 기다리면 `잠시 대기`, 계획 모드로 일하면 `계획 세우는 중`으로 보입니다. 작업 수와 펫 동작은 그대로입니다.
- **사용량 100% 알림:** `Codex 잔여 0%` 대신 `Codex 사용량 한도 도달`로 알립니다.

## Claude Code

- **백그라운드 작업이 남은 완료:** Claude Code가 백그라운드 명령(예: 띄워 둔 앱)이나 하위 에이전트를 남기고 응답을 마치면, 그때 완료를 알리고 행에 `완료 · 백그라운드 N개`를 보입니다. 전에는 `백그라운드 N개`로만 남아 세션이 다시 깨어나기 전까지 완료 알림이 없었습니다. 결과를 읽으러 다시 움직이면 작업 중, 마무리하면 완료가 한 번 더 나옵니다.
- **창 열기:** VS Code 터미널에서 돌린 Claude Code 세션의 말풍선 `창 열기`가, 세션 도중 들어간 워크트리 폴더가 아니라 세션을 시작한 폴더의 VS Code 창을 엽니다.

## 연결

- Codex·Claude Code 연결이 이 PC의 다른 Watched Kettle 실행본(설치판이나 소스 실행)을 가리키고 그 프로그램이 있으면 "연결이 풀렸어요"라고 알리지 않습니다. 실행본들이 같은 이벤트 폴더를 써서 작업 상태가 그대로 오기 때문입니다. `연결·진단`에는 "다른 Watched Kettle 실행본으로 연결돼 있어요"와 `이 실행본으로 옮기기`가 보입니다.
