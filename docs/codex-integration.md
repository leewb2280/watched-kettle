# Codex 연동

## 대화 조회와 공유 실행 연결 (2026-09-14)

사용자가 대화 읽기를 켜면 조회 서버에서 프로젝트·대화 목록을 읽는다. 최근 기준은
`updated_at` 내림차순이다. 긴 원문은 `thread/turns/list`와 `thread/items/list`를 순서대로
읽어 처리하며, 조회 전후 메타데이터가 달라지거나 중간 페이지가 실패하면 분석 실패로 표시한다.
페이지 기능이 명시적으로 미지원일 때만 제한된 전체 조회로 폴백한다. 원문은 외부 AI에 보내지 않는다.

실행용 어댑터는 설치된 CLI의 `app-server proxy`로 Desktop 공유 연결을 시도한다.
조회·전체 실행 관측·기존 대화 이어서 실행·승인 전달·소유한 실행 중단을 각각 검증해야
자동 실행을 허용한다. 계정·연결 세대가 바뀌거나 관측이 오래되면 배정을 차단한다.
별도 서버의 로드 목록을 Desktop 전체 목록으로 간주하지 않는다.

현재 Windows 앱의 기본 서버 통신은 앱 전용 stdio이며, 프록시가 찾는 기본 공유 소켓은 없다.
실제 진단은 주소 부재와 Windows 소켓 오류 10050을 기록한다. 읽기·작업 저장은 제공하되 실행은 잠근다.
실제 공유 연결에서 시작·완료·승인 수락/거절·중단·재연결·수동 실행 충돌 검수가 남아 있다.

## 입력 경로

공식 lifecycle hook을 우선 사용합니다. Windows 샌드박스가 사용자 전용 로컬 파이프를
차단하면 Git에서 제외된 짧은 수명의 큐로 전달합니다. 공식 이벤트가 없을 때만 Codex
세션 JSONL의 허용된 메타 이벤트를 읽기 전용 폴백으로 관찰합니다.

두 경로에서 같은 이벤트가 도착하면 공식 hook을 우선하고 한 번만 반영합니다. JSONL은
권한 승인이나 Codex 제어에 사용하지 않습니다.

## 전달하는 정보

상태 판단에 필요한 source, event, session ID, agent scope, tool ID와 성공 여부만
전달합니다. prompt, command, 작업 경로, transcript, 파일 경로와 도구 결과는 전달하지
않습니다. 일정 알림 메시지는 120자로 제한하며 큐 폴백에서는 최대 60초만 유지합니다.

## 연결 실패

사용량 작업 스레드의 공통 계정 확인기는 사용량 기능 활성 여부와 관계없이 시작 시와
60초마다 짧게 실행한 별도 App Server에서 `account/read` 및 한도 응답의 계정 식별자를
확인한다. 기존 App Server는 인증 파일 교체 후에도 이전 인증을 캐시할 수 있으므로
이 확인 프로세스는 매번 새로 생성하고 완료·실패·시간 초과 시 종료한다.
`auth.json`은 내용 대신 파일 메타데이터만 2초마다 확인하며 변경은 500ms 동안 모아
재확인한다. OS 자격 증명 저장소 방식은 주기적인 새 프로세스 확인으로 보완한다.

확인된 계정 변경은 사용량 및 대화 메타데이터 조회의 재연결로 전달하고 기존 계정의
진행 중 요청과 화면 상태를 무효화한다. 파일만 바뀐 동일 계정의 토큰 갱신에서는
연결을 새로 만들되 프로젝트 활동의 계정 변경 초기화는 실행하지 않는다.
로그아웃 뒤에도 계정 확인은 계속한다. 네트워크 오류는 로그아웃으로 간주하지 않는다.

일반 계정 갱신 알림은 실제 계정 전환의 증거가 아니다. 진행 중인 계정 조회가 있으면
그 응답으로 확인하고, 별도 확인이 진행 중이면 중복 알림을 합쳐 기한을 연장하지 않는다.
같은 계정의 확인 성공은 기존 연결을 유지하고 필요한 한도 조회만 이어간다.
확인 중 표시 자체와 계정 ID 누락은 재연결 사유가 아니다.
인증 파일 변경 세대는 실패 후에도 유지하며 새 연결의 초기화 성공 시 반영한다.
로그인 완료·응답 식별자 불일치·인증 파일 변경은 일반 알림보다 우선하여 다시 검증한다.

수동 새로고침은 GUI 접수 시부터 30초 제한을 적용하고 워커의 실제 응답으로
성공·부분 성공·실패를 구분한다. 이전 요청의 응답과 작업 큐의 오래된 화면 결과는
요청 ID 및 계정 세대로 차단한다. RPC별 제한은 10초다.

실제 CLI의 캐시 동작은 `python -m scripts.check_account_switch`로 검사할 수 있다.
이 검사는 임시 Codex 홈과 합성 인증만 사용하며 한도 RPC는 대역 처리한다.
실제 계정 두 개 및 OS 자격 증명 저장소 전환 검증을 대체하지 않는다.

hook, app-server, 파이프 또는 JSONL을 사용할 수 없으면 해당 기능만 비활성화합니다.
연동 오류가 Codex 작업이나 펫의 기본 애니메이션을 중단해서는 안 됩니다.

## 전역 hook 관리

전역 hook 변경은 설정창의 `연결·진단`에서 미리보기를 확인하고 사용자가 명시적으로 적용할 때만
실행합니다. 기존 hook을 보존하고 변경 전 백업을 만들며 Watched Kettle가 관리하는
항목만 복구하거나 제거합니다.

## 계정·기기 분리와 로그 읽기 기준

계정과 기기 관측을 분리하고 UI shell과 작업 흐름을 분리한다. 설치 의존성의 기준은 `requirements*.txt`이며 pyproject의 프로젝트 정보는 wheel 배포 계약이 아니다. JSONL의 활성/보관 로그는 공통 제한 tail 커서로 읽고 시작 replay는 알림을 억제한다. heartbeat는 활동 상태 유지에만 사용한다.
